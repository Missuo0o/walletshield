# 当前覆盖范围与剩余限制

[English](CURRENT-COVERAGE.md) · [简体中文](CURRENT-COVERAGE-zh.md)

本文记录 v0.4.1 完成正确性、模型校验、身份与依赖修复后的当前能力，不是准确率认证。安装、配置和启动见[中文 README](../README.zh-CN.md)和[使用手册](USER-MANUAL-zh.md)；逐配置的准确字段见[取数与能力边界指南](AI-COVERAGE-GUIDE-zh.md)。

WalletShield 对单个未签名 EVM 请求提供**签名前风险提示**。按当前产品范围，不强制阻止，不在签名后持续监控。**30 个分析配置、66 个代表性本地案例（51 笔交易、15 个消息，涉及 25 个配置）不是风险覆盖率。** 其他方法、部署、状态和恶意输入可能表现不同。

当前检查使用钱包提供的未签名请求、来源 origin/网络元数据，以及成功取得的 RPC、情报和模拟证据。Muse 评价可观察请求信号，包括支持范围内的来源、消息和请求不一致。链/provider/执行上下文指技术观察。历史报告与验收文件保留原始记录，不被删除或改写。


## 先区分入口

| 入口 | 已实现行为 | 边界 |
| --- | --- | --- |
| MetaMask 交易洞察 | 配对 Snap 转交未签名 EVM 交易并显示后端报告 | 钱包必须实际交付请求；在钩子前失败或拒绝，不会自动得到评估。 |
| MetaMask 消息洞察 | 配对 Snap 转交支持的 personal/typed 消息 | 签名前尚无生成的资产签名可验证或消费；provider 链快照不等于绑定请求的网络。 |
| 开发者明确调用 API | 支持 permission/session/UserOperation/network/read-only 摘要分析 | 是手动输入，不是 Snap 全局自动拦截，也不执行所提交 RPC。 |
| 公网连通检查 | 验证配置的 RPC 链/区块及可选账户状态 | 不产生风险分数，也不构造资产交易。 |
| 托管登录和 Snap 配对 | EOA 控制权证明、地址绑定凭据、按所有者隔离报告 | 登录与资产授权分开；不支持合约钱包/ERC-1271 登录。 |

准确的 30 个配置定义在 `src/security/coverage.ts`。没有可执行代表性钱包实验室案例的 5 个配置是 raw `eth_sign`、permission/session、UserOperation、网络配置与只读 RPC。后端支持摘要分析不能描述成钱包自动防护。

**EIP-7702 尚未端到端覆盖。** 当前能观察已有委托标记，并读取同一区块下的一跳委托目标代码/hash；这不等于验证新 authorization list、审计委托实现或证明实际权限。不支持的授权/交易类型字段会明确保留缺口，不会被移除来制造模拟成功。ERC-1271 签名接受及 ERC-4337 账户/bundler/paymaster 执行也仍不完整。

## 新增候选适配器

本轮还增加 DAI 结构 Permit、ERC-3009 单次转移授权、Safe 结构控制/执行、有界递归封装摘要、V3 仓位状态、部分桥提款/完成参数和通用 withdraw(uint256)。它们是有边界的候选适配器，不是全协议支持。已确认 nonce 仍固定区块，另有独立未固定的节点 pending nonce 视图，不取得原交易内容或替换规则。66 个钱包案例现包含 8 个简化账户交易和 4 个 DAI/ERC-3009 候选签名；其他新路径有 API/代码测试，不代表官方协议或公网钱包验收。详见[扩展能力与验收边界](EXTENDED-COVERAGE-2026-10-22.md)。

## 本轮具体修复

- 支持的 EIP-712 无符号整数在解释前统一等值十进制、十六进制与前导零表示，同时保持被签 digest 不变。没有实际签入的额外 JSON 属性仍不能制造签名权限。
- 链上 Permit2 的两层 allowance 独立读取；一层失败不会抹掉或替代另一层，读取成功也不认证合约。
- 零地址按字段角色解释。支持的 NFT approval/Permit 撤销不再误报为 NFT 销毁；真实转账/burn/所有权变更分别保留语义。
- transferFrom 区分资产 owner、调用者和接收者。当前余额不足描述为执行/敞口问题，不再误说成授权覆盖未来入账。
- AI 的 nonce/domain 断言检查覆盖摘要、原因、各维度、行动建议和缺失数据，包括条目索引、匹配方向、否定和条件性建议；必须有对应实际证据。**自然语言规则只是部分防护，不能证明每个句子都正确。**
- 账户/provider/断开连接和加载失败会清除历史与详情；取消/延迟异步响应不能恢复旧身份资料，当前所有者列表没有的选择会清空。本地模式仍是同机共享工作台历史；托管模式才实施按身份隔离。
- 托管配对原子且持久化限流：**每分钟每地址 4 次、服务端观察 IP 12 次、全局 60 次；每地址最多 4 个活动 Snap 凭据，全局最多 8192 个**。成功重配仅轮换该 owner 最早到期的凭据，拒绝不改变已有凭据也不扣签发计数。过期 token/旧限流记录使用索引清理。全局上限是初始服务容量策略，不是无限公众规模。托管 Fastify 只信任回环代理转发的客户端 IP；附带的 Nginx 示例用远端客户端地址覆盖 X-Forwarded-For，部署应保留该可信边界，不能信任任意转发头。

## Muse 分数的含义

新数值只由 `muse-wonder-1.0` 给出：0–100 整数或诚实的 `null`。没有本地权重、最低分、固定数值分档或失败兜底。六个定性维度引用证据：权限、敞口、执行、身份、协议和诱导。缺少信誉不等于身份恶意，熟悉名称也不证明真实身份。

评估范围记录此次请求实际未完成的检查与缺失证据；任何未知检查/缺口、模型发现的缺失、过旧/缺失/未来时间戳或同高度冲突哈希都会阻止整体 low 或 strong 证据支持程度。完整 complete 与缺失列表继续显示；包字段为 assessment_scope，报告属性为 assessmentScope，策略名 observable-request-v1。 即便允许输出，也不强迫模型给 low、strong 或数字。

范围内 low 只表示在已取得证据和明确限制内没有发现明显问题，不证明收款方合法、链下诚实、证据齐全、未来安全或损失概率。其他维度未知时，已知危险权限仍可能支持条件性数字；所有维度都缺乏实际支持时不接受数值。拒绝输出/修复流程不会制造分数。

## 情报、限制与缺失输入

- **GoPlus：** 仓库默认关闭；本次复核的开发机明确启用。各安装查看 `/api/security/status`。在支持链上查一个主要代币、最多三个明确交易对手及规范化网站 origin，不遍历全部路径资产、历史对手或任意网站正文。缺失/陈旧字段和未命中都不证明安全。
- **RPC：** Infura/可信节点提供链上事实，不负责连接用户钱包，也不自动理解所有协议。增加读取需要经测试的 ABI/版本适配；不支持链、缺少归档状态、限额、错误回复和重组都可能存在。
- **模拟：** 只描述记录的分叉状态，日志/资产/调用有界。卖出成功一次不是未来可卖；失败也可能并非诈骗。有些交易字段/类型不支持，明确保留缺口。
- **需要额外可信服务：** 价格/报价/流动性、官方部署/源码/构建身份、管理员关系和更广信誉登记；不能由模型记忆或 Infura key 凭空产生。
- **需要钱包/dApp 配合：** 未暴露的 permission/session/UserOperation、raw hash 原文和依赖方 nonce/session 存储。提示词不能恢复从未收到的数据。
- **本工具未确立的能力：** 非 EVM、设备恶意软件/密钥泄露、交易所内部、任意代码完整性、未来价格/升级/黑名单/排序/跨链到账、资金追回。强制阻止和签后监控按产品范围不做。
- **可靠性仍待测量：** 没有独立留出的标注测试集、误报漏报率、分数校准、重复稳定性及完整对抗评估。本地通过案例不能替代这些指标。
- **公众上线仍需：** 真正 HTTPS 部署、目标 Snap 发布/分发、浏览器钱包验收、备份恢复、保留/删除政策、负载与故障测试和运维复核。Infura 连通不等于产品上线。

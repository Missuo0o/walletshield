# 订单证据、弃权与分叉 trace 修复 — 2026-10-23

[English](ORDER-TRACE-FOLLOWUP-2026-10-23.md) · [上一轮可靠性改进](RELIABILITY-FOLLOWUP-2026-10-23-zh.md)

本轮解决两个具体问题：未解释语义的自定义订单曾出现“出分/弃权”不一致，以及上游不提供 trace 时已有隔离分叉无法向 Muse 提供这部分执行证据。不承诺所有操作都有数字，也没有测得独立准确率。

## 本轮修改

- 先前简化的 `Order` 实际是类似 ERC-20 字段的自定义签名，**并非完整 NFT 市场订单**。主订单案例改为支持的完整 `OrderComponents` 类型图，使用钱包当前拥有的本地 NFT，换取明确原生币数量。自定义订单作为单独负对照保留，语义仍明确未知。
- 新增可选 `LabOrderVerifier`，提供固定实验域及只读 information/counter/status getter。它**不实现履约、取消、nonce 消费或签名验证**。`npm run deploy:lab` 在有效旧实验环境中只添加缺少的合约，保留原有地址与资产。订单测试仍需先准备 NFT；后端不替用户签名或提交订单。
- 采集器精确比较签入域哈希与候选 `information()` 返回值，查询前八个 offer；增加 ERC-1155 按 owner/id 查余额、ERC-20/ERC-1155 签入数量端点与余额比较，以及 NFT 所有者差异提示。counter/status 只作为未经认证的候选返回值，不因 ABI 相似就认定真实市场、spender/conduit 或可成交。
- 新增 `numeric_assessment_basis`：语义未知的 typed 请求，仅有哈希、编码成功、地址、代码存在、泛化权限警告或无关余额时，不能支持数字。只有本请求绑定的实际不利证据，才可能支持有条件评分；否则 Muse 返回 `null/unknown`。提示词和校验器执行同一边界，不计算固定分、下限或兜底分数。
- 订单域比较必须绑定实际完整订单、verifier、offerer、order hash、重算签入域哈希以及链/区块/哈希/时间。比较相等不认证身份、签名有效性或订单状态语义；也补上了对“verifier 是官方”的无依据断言拦截。
- 启用分叉模拟后，**复用同一个已有临时 Anvil 分叉**，在本地执行之前只读运行 `debug_traceCall`。前后核对来源和子节点链、基础区块信息，保留受支持的原始交易字段；即使后续本地执行失败，已完成的 `call_trace_fork` 仍保留。调用帧只作为 execution 维度事实发送给 Muse，服务商和隔离分叉观察分开显示。

分叉 trace transport 只接受三种只读方法，限制为总计 6 秒、单请求 1.8 秒、750 KB、128 帧、深度 20。不向上游发交易，不取得真实签名，不再开第二个分叉。仍要求 Anvil、所需历史状态、正确快照和现有模拟预算可用；不支持的交易封装、缺失历史、重组、超限、超时继续保留缺口。

## 使用步骤

1. 在自有本地链运行 `npm run deploy:lab` 添加可选订单合约，原合约和资产保留；当前开发环境已经完成。
2. 后端保持 `ENABLE_FORK_SIMULATION=1`；当前本地环境已启用。此路径不需要另买 trace 服务，但仍要求普通 RPC 能提供所需历史状态。
3. 构建并重启服务，刷新网页；Snap bundle 更新后在 **Wallet setup → Reload and pair Snap** 重新加载配对。
4. 准备本地资产，选择 **NFT order components**，在 MetaMask 核对 NFT、原生币对价、时间、verifier 和 WalletShield 报告。**Custom unresolved order** 用于验证未知协议边界，可能没有数字。签名或取消由用户在钱包决定。
5. `npm run test:trace` 验证上游不提供 trace 时的隔离回退，不调用 Muse 或浏览器钱包；`npm run test:v3` 运行已有隔离 V3/状态场景；`npm test` 运行单元和回归测试。

真实市场/conduit 身份、criteria proof、任意自定义协议含义、未生成签名的实际接受及未来履约仍未证明。Trace 不等于完整资产覆盖、honeypot 认证或未来执行保证。合理弃权继续保留，直接取消它会掩盖这些缺口。

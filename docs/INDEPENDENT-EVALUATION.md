# Independent-label risk evaluation

WalletShield now has a **read-only external-label evaluation workflow**. It closes the missing measurement-tooling gap; it does not manufacture independent labels or establish a current accuracy percentage. Existing maintained fixtures still measure decoding, evidence validation and regression behavior. They are not an independent benchmark.

The command makes **zero model calls, zero RPC calls**, reads neither `.local` nor the report database, and never writes either input file. It compares previously captured predictions against a supplied frozen label manifest. Nothing here changes production scores, adds fallback scores, averages dimension weights or turns the Muse number into a loss probability.

## What labels mean

The supported target is `expert-adverse-risk`: a qualified reviewer judges whether the **specific unsigned request and evidence available at its timestamp** contains a material adverse security risk under a documented policy.

| Label | Meaning |
| --- | --- |
| `adverse` | The reviewed request/evidence supports a material adverse security-risk conclusion under the policy. It does not assert a known percentage of future financial loss. |
| `benign` | The reviewed request/evidence fits the policy's benign/control case. This does not certify a contract or guarantee future safety. |
| `indeterminate` | Review cannot establish either binary class from that packet. Numeric scores are counted separately; no automatic credit is awarded for abstention. |

For example, a reviewer may label a request whose spender is independently confirmed malicious as adverse, with the exact evidence and source recorded. An unlimited allowance **alone** must not automatically become an adverse label: legitimate applications also request it. A smaller amount alone must not automatically become benign. A `review` assessment means the model deferred a binary decision; it is not an attack label or monetary outcome.

`labelBasis` records `expert-review` or `verified-incident`. A known incident must still be mapped to the relevant request and time; post-incident information unavailable to the model must not silently become model input. Declare that sampling choice. Keep different targets, such as actual loss over a defined time horizon, in a separate future evaluation protocol.

## Prepare and freeze an external dataset

1. Obtain independently reviewed cases, including benign cases, adverse cases and difficult unknowns. Document selection, source population, chain/protocol distribution, incident timing and the label policy. De-identify data and retain only data you are authorized to use. Do not include secrets, private conversations or signing material.
2. Store the exact evidence packet privately and record its SHA-256 in `evidenceSha256`. The hash must identify the **same frozen packet** later supplied to the model, not a mutable URL or a newly collected block state. The evaluator verifies hash agreement, not the truth of the upstream packet.
3. Record reviewer identities/roles, review times, rationale and a verifiable source reference. Labels must not be generated by the evaluated Muse run or inferred from its scores. Resolve reviewer disagreement under the label policy before freezing; use `indeterminate` when unresolved.
4. Separate `development` and `holdout`. All variants/retries of one source incident or related scenario share `groupId` and remain in one split. Identical evidence hashes cannot cross splits. Mark any prompt-tuned case `usedForPromptTuning: true`; it cannot remain holdout.
5. Freeze the complete manifest before generating evaluation predictions. Record its hash:

```bash
npm run --silent evaluate:independent -- --labels=/private/path/labels.json --hash-only
```

6. Pin the model/version, prompt hash and collector version. Capture exactly one predeclared evaluation outcome per case. Keep provider failures, valid abstentions and `not-applicable` outcomes. Do not select the best retry; evaluate a new frozen run separately if repeating. Preserve retry/cost logs outside this small prediction manifest.
7. Put the frozen label digest in `labelsSha256`; each prediction records the matching packet digest and generation time. Run:

```bash
npm run --silent evaluate:independent -- \
  --labels=/private/path/labels.json \
  --predictions=/private/path/predictions.json \
  > /private/path/evaluation-run-001.json
```

The CLI limits each JSON file to 16 MB and rejects unknown fields/options, duplicate IDs/predictions, changed label digests, changed packet digests, inconsistent time ordering, declared tuning leakage, related groups crossing splits and identical evidence crossing splits. Output goes only to stdout; choose a new output filename to preserve previous runs.

The parsers and TypeScript types are in [`independent-evaluation.ts`](../src/evaluation/independent-evaluation.ts). Runnable **synthetic format examples** are in [`evaluation/`](evaluation/). Their reviewers and predictions are fabricated workflow examples and never establish actual model accuracy. Replace them with real independent review before using `provenance: "externally-reviewed"`.

## Interpret the metrics

Development and holdout metrics are reported **separately**. The report gives case counts and declared group counts; related cases are not presented as independent statistical samples. No confidence interval or population-wide success claim is computed.

| Metric | What it measures |
| --- | --- |
| Output counts | Numeric outputs, valid abstentions, failed outputs, not-applicable outputs and missing cases are all separate. A missing/error response is never counted as correct. |
| Numeric coverage | Numeric outputs divided by all cases; binary-label numeric coverage is also provided. |
| Binary decision coverage | `high` or `low` outputs divided by all binary-labelled cases. Numeric `review` responses defer classification. |
| Selective confusion metrics | `high` = adverse, `low` = benign, `review` = deferred. Precision, recall, false-positive rate and accuracy are computed **only among decided outputs**, with explicit numerators/denominators. There is no numeric threshold and no production score rule. |
| All-case rates | Correctly flagged adverse cases, false-low adverse cases and false-high benign cases retain unavailable/deferred cases in their denominators. Read these alongside coverage; a low false-low rate with many missing outputs is not high reliability. |
| AUROC | Whether higher numeric scores rank reviewed adverse cases above reviewed benign cases. Ties receive half credit. It is unavailable without both classes. Abstentions/failures/unknown labels are excluded, so the report explicitly states its selective scope. |
| Indeterminate cases | Counts numeric outputs and abstentions for unknown labels; neither is automatically declared correct. |

**Probability calibration is deliberately unavailable.** The current Muse score is a risk indicator, not a forecast of a specified loss event over a specified time horizon. Dividing it by 100 and calculating Brier scores or reliability bins would incorrectly imply probabilistic meaning. Independent ranking/classification results can guide subsequent improvements, but fitting a probability mapping would require a separate, appropriate outcome dataset and an untouched evaluation split.

## What remains external work

This implementation checks supplied records; it cannot prove a reviewer is independent, a timestamp is truthful, the holdout was unseen by a model, a source label is correct, or that a generation service really sent the packet whose digest it recorded. `externally-reviewed` therefore produces **external-reviewer-and-holdout-declarations-not-independently-attested**, not a certification. A hash makes silent edits detectable against the prediction manifest; it is not a signature, trusted timestamp or tamper-proof archive.

An actual accuracy result still requires independent reviewers, documented case sampling, frozen source material and predictions collected under that protocol. This task adds the safe measurement path and deterministic tests; it does not claim that those external data have already been obtained.

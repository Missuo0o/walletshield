## 当前评分与发布复核 · 2026 年 10 月 27 日

本轮各层验证与最终结果见[完整复测报告](FULL-RETEST-2026-10-27-zh.md)。下方带日期的 10 月 24 日章节说明此前实现，不能据此认为历史分数已经通过当前策略。

- **数量绑定的模型证据。** 当前结构化结果采用 `muse-evidence-v7-quantity-bound-facts`。资金敞口必须由明确允许的采集器/字段路径中的实际数量或经济比较支持，不能因为采集器确实运行，就把其全部标记、地址、大小、ID 或元数据都当作资金证据。纯来源元数据与未执行控制项标记不能单独支撑任何 low/review/high 维度。这些规则约束证据是否可用，不是固定加分、权重、分数区间或兜底数字；分数仍由 Muse 给出。
- **资产主体和单位保持区分。** 原生币余额绑定被观察账户；代币余额/额度绑定准确代币。分叉中嵌套的前后余额及带正负号的原始变化值，保留实际代币/原生币主体。金库份额属于金库，底层资产数量属于底层代币，借贷的账户基础单位不能改称某个代币余额或美元。反向兑换取得的输出属于输出资产，返还的输入及实际输入扣减属于输入资产，返还比例是实验结果。缺失绑定保持未确定；这些数量都不证明市场价格或未来损失。
- **Snap 报告必须对应捕获请求。** 展示建议前，Snap 会把后端报告与它实际收到的未签名交易/消息进行对应核对。不匹配报告不能为另一请求提供分数。这是请求关联检查，不是 Snap 执行的密码学证明，也不证明后端诚实。
- **最终发布字节接受验证。** 打包先统一最终 proposed name、npm 包身份、版本和仓库，再按最终 manifest/bundle/icon 计算校验和，并使用 MetaMask 官方 manifest/校验和工具验证复制出的发布产物。不能改完 manifest 后继续沿用旧校验和。它只准备产物，不代表已经发布或具备分发资格。
- **历史结果不重新评分。** 已保存的 v6 或未记录策略结果保留原分数及历史策略提示；打开记录不会再次调用 Muse，也不代表通过 v7 校验。新增结构/语义测试及合规模型回复仍不能测得独立标注的准确率或校准结果。

## 独立实现复核 · 2026 年 10 月 24 日

本次单独复核的过程和验证结果见[独立复核报告](INDEPENDENT-RECHECK-2026-10-24-zh.md)。既有带日期报告保留原计数和观察，不能据此声称旧结果已经通过新策略校验。

- **按字段绑定模型证据。** 新的结构化评估记录 `scoringPolicy: muse-evidence-v6-field-bound-facts`。`chain_context` 的原生币余额属于当次捕获的发送/签名账户，不能标成收款方或验证合约余额。所选事实必须支持对应维度：链 ID、代码哈希、普通地址、NFT ID 或单位元数据，不能因为同一个采集器还读取了余额就自动成为资金敞口依据。实际数量、比较和已观察的 NFT 所有权仍保留各自的有界含义；代码存在只能在明确允许时支持执行观察。数字仍由 Muse 给出，没有固定加分、权重或兜底分数。
- **分叉结束时核对来源。** 原始调用 trace、原始分叉执行、资产/权限/协议变化和派生反向兑换实验，共同接受结束时的来源链及规范区块头复核。来源绑定缺失、变化、畸形或无法复核时，整个分叉组都会丢弃；前面 trace 成功不能豁免后面的执行验证。私有分叉仍是独立状态，不向上游广播交易，也不保证未来安全。
- **钱包动作绑定可见选择。** 本地案例和公网签名检查会在创建交易/签名提示前，以及异步准备期间，核对捕获的 provider、实际账户和网络。连接、身份验证和 Snap 配对等设置动作也使用有界等待。账户/provider/网络变化或超时会结束当次动作，迟到的结果不能再创建新提示或恢复过时界面。超时不能替 MetaMask 取消已经弹出的请求；重试前请在钱包自行批准或取消。
- **等待后再次核对托管权限。** 网络读取、扫描和其他受保护的异步工作，会在返回私有数据或接受结果前重新验证凭据及其范围。上游请求进行中发生撤销，不会让迟到的完成结果继续获得授权。已认证但范围不符，与凭据过期/被撤销保持区分。已经发给外部服务的请求无法追回。
- **历史分数保留原策略。** 旧策略或未记录策略的已保存结果显示历史策略提示。打开记录不等于重新评分，也不表示已通过 v6 校验。新分析使用自己的证据，可能得到不同数字、拒绝无依据回复或合理弃权。离线重放和新增回归测试都不能测得 Muse 的独立准确率。

## 快照、声明与界面防护

- `pinnedRpc` 优先使用 EIP-1898 区块哈希选择器及 `requireCanonical: true`。只有提供方返回无效参数错误时，该方法才回退到区块号。区块号读取在前后核对链和完整区块头，整个关联采集组结束时再次核对原链、高度、哈希和时间戳；其他已确认状态的区块号采集组也进行前后核对。区块头缺失、畸形、变化或无法复核时，会丢弃该组 RPC 状态值和由其推导的结论，单独保留请求/密码学证据并记录缺口。
- 某个合约接口失败时，只有关联快照通过一致性核对，其他独立取得的事实才会保留。快照无法核实时，不会把已读成功的值继续挂在旧哈希下。不同采集器仍可能使用不同区块，pending nonce 仍是明确未固定的节点视图，分叉执行也有独立状态。这些核对不构成全局原子快照，不证明 RPC 诚实，也不保证未来执行。
- 确定性校验按声明所在的分句检查。“你应该批准”或另一句谨慎措辞，不能豁免相邻的无依据官方身份、安全、未来执行/卖出或事实性美元损失断言。真实的不确定表述和条件式核实建议仍允许。这是有界语言防护，不是每句话或分数正确的证明。
- 本地准备/清理捕获同一个账户和 provider，钱包动作共用 120 秒期限，账户/链读取最多 5 秒，钱包提示最多 60 秒。超时后网页解除等待，不自动重发切换/添加网络请求。仅未知本地网络可用链 31337 和回环 RPC 添加一次，随后仍须确认链状态。资产显示遇到超时或已有待处理请求时停止继续弹窗。资金准备成功与钱包显示分开：拒绝、不支持或待处理的显示请求不会撤销已准备资产。请打开 MetaMask 自行批准或取消剩余提示；网页不能替钱包取消。资产清单另行刷新。
- 托管网页登录有效 8 小时，Snap 配对使用独立的 30 天期限。已知到期会更新对应界面；网页到期清除网页验证身份和私有历史，不把独立 Snap 凭据一并视为过期。受保护网页接口返回匹配的 `401` 时，只作废该请求实际携带的凭据，且在解析 JSON 前处理；旧请求的拒绝不会清除较新的登录。范围不匹配的 `403` 保留凭据。浏览器恢复焦点或可见时再次检查到期。尚未收到的撤销信息仍须通过认证响应或健康检查发现。

## 当前证据与接入新增能力

Muse 返回精简 `walletshield-selection-v1` 事实 ID，后端解析原始服务器事实、保存 `walletshield-facts-v1` 并保留严格引用和语义校验。历史完整事实仍可读，数字仍只由 Muse 给出，没有固定权重、下限或兜底。未解释语义的 typed 请求通过 numeric_assessment_basis 限定数值依据：哈希、代码存在、泛化权限标签和无关余额不能单独支持数字；需要本请求绑定的实际不利证据，否则保留 null/unknown。已解析范围可支持有条件评分，但不强迫模型出分。[可靠性改进](RELIABILITY-FOLLOWUP-2026-10-23-zh.md)说明评分分类、trace 回退和独立标签评估；没有真实外部标签时仍不能声称测得准确率。

交易 trace 依次尝试 debug_traceCall、trace_call，可配置后端专用 TRACE_RPC_<CHAIN_ID>_URL，但必须与主端点的链/区块/哈希/时间一致。有界调用帧只支持 execution 维度，不证明完整资产覆盖或安全；启用隔离分叉模拟时，已有临时 Anvil 分叉会在本地执行之前追踪原始调用，并在前后核对来源链及基础区块哈希/时间。该路径不要求上游提供 trace，但要求 Anvil、所需历史状态和有界分叉预算可用。服务商与分叉 trace 分开记录。严格白名单只读请求标记无需资产评分、不调用 Muse，隐私仍未评估。

后端部署登记/代码匹配、USD 参考价格源和维护式两链桥接路线核对已移除。已有 `.local/registry.json` 不再读取。基础交易/授权/签名解析、配置的 RPC 状态、部分 V2 路径（含已有原生币路径）、代币出资 V3 与通用分叉模拟、可选 GoPlus 和 Muse 评分保留。`ENABLE_SOURCE_VERIFICATION=1` 仍独立启用有界 Sourcify 源码匹配观察；它不是官方部署登记或代码审计。

有界证据包括 Seaport 签入承诺、候选域哈希/数量/所有权比较、Permit2 witness 外层承诺、UserOperation 参数/代码/费用观察、EIP-7702 元组密码学/有条件状态、原始分叉交易前后部分权限/金库/借贷状态、代币出资的 V3 路线实验和候选池状态。Seaport 候选 counter/status getter 可读取为未认证观察，不据此认定当前协议取消、成交或 nonce 语义有效；不猜测实际 spender 或直接授权。EntryPoint keyed nonce/deposit 检查未提供。dApp 包装器须主动接入，不是全局钱包拦截；托管 ERC-1271 只验证本次登录，不验证未来资产签名。

Wallet and network 页面提供有界只读 RPC 能力观察：固定区块调用、一次历史余额和固定 trace 探测。成功不是完整 archive/trace 保证。源码核对仍是独立可选后端配置，公网页面不显示其状态。Public networks 的切换按钮通过选定钱包 provider 直接调用 `wallet_switchEthereumChain`，不调用接入 SDK、风险扫描或 Muse，由钱包处理确认。

`npm run evaluate:ai` 默认运行固定哈希的合成校验器检查，不请求模型/RPC，不代表在线 Muse 准确率。付费评估必须显式指定 `--live --confirm-paid`、案例和调用预算，不会自动运行。

## 1. 请求入口与组件分工

| 组件 | 实际职责 | 不能据此得出的结论 |
| --- | --- | --- |
| 网页 | 从通过 EIP-6963 发现的 EIP-1193 provider 中选择一个，连接账户、检查已配置网络、发起用户明确选择的钱包请求并显示报告 | 连接账户并不让网页自动检查其他 dApp 的无关请求。 |
| MetaMask Snap | 接收钱包支持的未签名交易/消息钩子，将请求发送到构建时确定的后端，并在用户最终决定前显示分析提示 | 它不是权限、会话、UserOperation 或任意钱包 RPC 的全局拦截器。 |
| Fastify/Zod 后端 | 校验输入、解码已知结构、选择采集器、保留证据与未知项、在配额内调用 Muse、校验输出并保存报告 | Origin 不是托管模式的身份认证。解码出方法并不等于已认证协议身份。 |
| Muse Wonder | 评价所提供的证据，返回带引用的维度、可选数值、不确定性与建议 | 当前未给模型配置浏览、钱包访问、RPC 工具或函数调用工具。模型不能凭空补出实时链上数据。 |

自动入口仅包括 MetaMask 实际交给 Snap 的 EVM 交易和消息请求。其他钱包 RPC 必须明确提交。

“自动入口”表示请求具备进入钩子的条件，不保证分析成功。安装、配对健康状态、钱包是否交付请求、后端可用性、网络配置正确与证据采集成功，是分别需要满足的条件。钱包可能在交付钩子前就拒绝请求。消息可能授权以后的支出，而不立即广播交易。

产品只提供签名前建议。你在钱包中决定是否继续；工具不强制阻止，也不在签名后持续监控。

本轮数量与角色修复：支持的 EIP-712 无符号字段在解释前统一等值十进制、十六进制与前导零表示，保持被签 digest 不变；未签入的 JSON 字段不创造权限。零地址按角色解释，支持的 NFT approval/Permit 撤销不误报成资产销毁；transferFrom 区分资产 owner、调用者、接收者，当前余额不足不再误说成授权覆盖未来资金。

| 独立 Snap-provider 快照 | 只读 `eth_chainId`，附来源与观察时间，单独存放在 `signature.providerContext` | 不绑定发起 dApp 或请求时刻。domain 匹配不证明请求网络；不一致只构成上下文警告。 |
| 隔离 Anvil 分叉：`simulation.ts` | 验证上游链与基础区块哈希；只在临时本地分叉执行；记录执行区块、原生币变化/gas、发现的标准资产和有限调用 | 保留所供 gas/费用/nonce；缺少 gas 时使用明确的默认值。不伪造用户余额/权限，也不向上游广播。隐藏/非标准资产与未来状态仍不完整。 |
| 部分 V2 往返实验 | 买入、只授权获得的代币，再反向走支持的路径，观察卖出/返回量/gas | 仅支持部分方法，且要求相同接收方。卖出最小量为零只用于分叉实验。损失包含手续费/价格影响，不是纯税率。 |
| GoPlus（可选） | 支持链发现；规范化的网站 origin、最多八个解码代币候选、八个明确交易对手地址；部分钓鱼/蜜罐/税费/控制权标记 | 默认关闭。不支持的链、缺失字段、失败和未命中都不等于安全；不会检查路径上的每个资产。 |
| 规则 / 路由器 | 工具计划、可观察的权限/价值/期限/账户/domain 信号及明确缺口 | 只有定性观察，没有加分项、分数下限、固定权重或数值兜底。选中工具不等于观察成功。 |
| Meta Responses API | 固定使用 `muse-wonder-1.0` 评价白名单证据包，并引用实际存在的证据 ID | 分数是未经校准的风险指标，不是损失概率或真实性证书。 |
| 托管 EOA / 已部署合约登录 | 精确的一次性 domain/URI/nonce 登录挑战，恢复签名者，哈希后的网页/Snap 凭据，按所有者隔离的报告与按地址配额 | 与资产风险分析分开；支持的已部署 ERC-1271 合约仅核对本次登录，不授权资产。 |

这里的“RPC 适配器”指**经过测试的特定协议读取/解码代码，加上可用且可信的节点**。它不是“连接钱包”，也不是填入一个 Infura key 就能自动识别所有协议。节点提供链上读取能力；某类协议还需要对应的读取、解码、语义处理与测试。

GoPlus 的仓库默认仍关闭；本次复核的开发机已明确启用。其他安装请查看 `/api/security/status`，不要假设继承本机开关。范围已扩为最多八个代币候选、八个明确交易对手；每轮最多十八个网络请求、四路并发、单请求 1.8 秒、总共 7.5 秒，响应缓存三十秒，缓存容量 256 项；支持链列表缓存一小时。

已确认状态采集器验证并固定自己的读取。额外的 pending nonce 明确为单节点未固定视图，可能缺少私有/远端交易，不包含原交易内容、取消意图或替换费率规则。不同采集器的区块与观察时间可能不同，完整报告不是全局原子快照。接口读取失败时，其他独立 RPC/balance/code 成功结果只有在关联快照组通过链/区块头一致性检查后才保留；区块头缺失或不一致时丢弃整个关联状态组。分叉执行在记录的基础区块之后挖出子区块。工具是否被选择/可用，与数据是否成功采集分开记录。

证据质量清单会标记：相对报告创建时刻已超过 5 分钟的观察、缺失/无效时间戳，以及领先超过 30 秒的时间戳。这些是新鲜度诊断，不是数值风险阈值；观察时间也不能证明 provider 数据本身有多新。`pinnedRpc` 优先使用区块哈希选择器。区块号已确认状态组在采集前后核对链和完整区块头，缺失或不一致时丢弃整个关联状态组。这不能证明 provider 诚实、形成全局原子快照或防止未来重组。同一链同一高度发生哈希冲突时，需要新的独立检查，并且不能给出整体低风险或强证据置信度。

## 3. 模型输入的准确字段

`src/security/ai.ts` 中的 `evidencePacket` 函数提供以下容器，不会把整个原始请求都发给模型。

| 字段 | 提取内容与限定条件 |
| --- | --- |
| `version`, `scoringPolicy`, `createdAt`, `reportSource`, `evidenceComplete` | 报告格式、服务端当前校验策略、时间、实际或合成来源，以及明确的证据缺口状态。旧策略不会在读取时被改写。演示观察不能当作当前真实链上事实。 |
| `chainId` | 交易/请求网络；签名没有绑定请求的链时为零。typed domain 可作为声明的网络来引导读取。 |
| `origin` | 只保留 HTTP/HTTPS origin，去除 URL 凭据、路径、查询和 fragment。 |
| `quality` | 状态数量；各来源的已观察/未知数量；在可用时含链、区块/哈希/时间的快照；观察超过 5 分钟及缺失/未来时间戳标记；混用上游区块的链和同高度冲突哈希；采集渠道和钱包凭据归属。数量与年龄标记不是安全/置信度百分比。 |
| `evidence_admissibility`, `claim_support` | 服务端给出各维度相关的实际观察 ID，以及有界基本调用/分叉执行/分叉卖出支持，约束引用和部分事实断言，不是数值权重或全面真实性证明。 |
| `requestSummary` | 交易：`from`, `target`, `valueWei`, `selector`, `calldataBytes`。签名：`from` 和 `method`。其他 RPC：`method`。此处不含完整 calldata/digest。 |
| `feeParameters` | 所供 `gas`, `gasPrice`, `maxFeePerGas`, `maxPriorityFeePerGas`, `nonce`，均为精确的十进制整数字符串；不凭空补齐缺失字段。 |
| `unsupportedTransactionFields` | 明确标记不支持的执行字段；不会把精简后的替代交易描述为等效执行。 |
| `operation` | 类别、候选标签、解码字段、目标、token/standard，以及权限/复杂度标记。字段必须结合资产标准和单位理解。 |
| `checks` | 证据 ID、status、title/detail、source、observedAt 及结构化数据：已取得的区块/余额/代码、权限、协议返回值、签名状态、分叉变化/调用或情报。 |
| `missing_checks` | 明确缺失数据与 unknown 检查项的并集，包括报告不完整状态。缺失观察不算成功检查。 |
| `assessment_scope` | 服务端推导的可观察请求范围与未完成检查/缺失清单；报告属性为 assessmentScope，策略名为 observable-request-v1。这不是数值分数，也不会把不完整报告改成 complete。 |
| `request_data_scope`, `snapshot_consistency`, `quantity_conventions` | 有界提取/来源记录、各采集器快照差异，以及精确的数量/单位解释。 |
| `analysis_dimensions`, `score_meaning` | 必须带引用的六个维度，以及独立的 0–100 或 null 风险指标规则。 |
| `structured_fact_candidates` | 白名单精确观察、可支持维度和遗漏清单；模型选择 ID，后端解析原始事实，不让模型改写观察。 |

普通消息最多预览 1,600 个字符。通用 RPC 摘要通常检查最多 5 层嵌套、每个数组 16 项、40 个可识别标量字段及 8 个目标地址。即使模型只收到摘要，完整请求数据仍可能保存在后端。模拟处理有限日志（最多 256 条）、发现的资产（最多 32 个）和调用（最多 128 次）；明确资产和 ID 读取另有更小限制。截断属于覆盖缺口。

除非已读取同一资产的 decimals，否则原始数量字符串均表示最小单位。`valueWei`/原生币余额/`gasWei` 的单位是 wei；`gas` 是执行单位数量，费率单位是 wei/gas；`nonce` 是计数器。份额不同于底层资产。NFT ID 不是财务数量。`roundTripReturnPercent` 已经是百分比，且不只包含税费影响。Aave 结构的 `healthFactor` 以 1e18 表示 1；`Base` 字段的计价币种不会自动得到验证。没有价格来源，就不能推断美元损失。

DAI allowed 是参考语义推导，不是另一签入数量。ERC-3009 为单次精确转移，Permit2 transfer 为单 nonce 上限，均非持续 allowance。ERC-3009 当前余额不足时标明 balanceCoversDeclaredAmount=false，不假设可消费较小数量；条件性 allowance/上限比较不代表未来损失。空 calldata 的 DELEGATECALL 是委托执行，不是原生付款。具体测试与身份边界见[扩展说明](EXTENDED-COVERAGE-2026-10-22.md)。

## 4. 全部配置：尝试取得的证据与剩余缺口

以下字段描述会尝试的路径。只有成功观察才成为事实。配置缺失、接口不可用、超时及不支持的语义都会留在证据包中。**候选解码、自动入口和完整协议验证，是不同的能力声明。**

### 1. 原生币转账 / 合约接收方

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 通用交易检查；接收方身份未验证。
- **取得后提供的字段/证据：** `from`, `to`, `value`, `chainId`、来源 origin、gas 和所供费用参数；已验证的 RPC 链/区块、`nativeBalanceWei`、目标代码和一跳委托代码；已确认 nonce、所供费用与观察到的 base fee 的比较；可选分叉原生币变化、gas 与有限调用；仅在启用时提供可取得的地址和网站情报。
- **仍未知：** 转账不证明接收方身份、目标网络正确、未来诚实或最终费用。
- **可扩展方向与边界：** 增加可信地址簿/名称解析、已验证接收方、支持链策略和费用参考。这些仍不能保证接收方诚实。

### 2. ERC-20 转账

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 标准 transfer 候选与部分资产变化。
- **取得后提供的字段/证据：** 从 `transfer(address,uint256)` 读取代币合约、接收方和原始数量；可读的 symbol、decimals、余额、资产代码和固定区块；可选的已观察余额变化、超额支出证据和代币情报。
- **仍未知：** 名称可能伪造。非标准费用、rebase、无事件资产和货币估值仍不完整。
- **可扩展方向与边界：** 增加可信代币登记、价格、标准与协议适配器。任意合约仍可能使用未知存储或欺骗性接口。

### 3. NFT / 代为转移 / NFT 批量转移

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 常见 ERC-721/ERC-1155 方法；共用 selector 时需要检查标准。
- **取得后提供的字段/证据：** 解码转移中的 owner、recipient、tokenId 或 ids/amounts；ERC-165 声明；每个资产最多 16 个 ID 的 `ownerOf`/`getApproved` 或 ERC-1155 `balanceOf`；部分 `isApprovedForAll` 状态；可选分叉所有权/余额变化和有限调用。
- **仍未知：** 合约可能谎报标准。系列真实性、价值、全部回调和非标准资产行为未验证。
- **可扩展方向与边界：** 增加可信系列、更多 ID/回调适配器和价格。真实性与市场价值仍需要独立证据。

### 4. 单项授权 / 撤销 / 链上 Permit

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 常见权限参数；spender 身份仍不完整。
- **取得后提供的字段/证据：** `spender`, `amountOrTokenId`、大额 allowance 标记，以及支持的 owner/deadline 字段；资产标准查询；支持时读取现有 ERC-20 allowance；当前余额、部分控制权、可选情报和分叉超额支出证据。
- **仍未知：** ERC-20 和 ERC-721 的 approve 共用编码。有限额度也可能恶意；链上 Permit 变体与未来支出未完全覆盖。
- **可扩展方向与边界：** 增加逐 NFT 权限、其他自定义 Permit 适配器、经验证的 spender 身份与历史。不能排除未来升级或权限滥用。

### 5. NFT operator 授权 / 撤销

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 识别面向整个系列的 operator 权限。
- **取得后提供的字段/证据：** 系列合约、operator 和 approved 布尔值；此次请求是否提高覆盖整个系列的权限；可读的部分 operator 状态；可取得的控制权、地址情报和分叉行为。
- **仍未知：** 当前和未来 NFT 敞口未完整枚举。operator 身份及后续用途仍未知。
- **可扩展方向与边界：** 增加持仓与逐 NFT 敞口、可信协议身份及更多 operator 状态检查。未来资产与行为仍不确定。

### 6. Permit2 结构的链上 allowance

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 常见四参数 approve 候选。
- **取得后提供的字段/证据：** `token`, `spender`, uint160 `amount` 和 `expiration`；独立读取底层 ERC-20 `allowance(owner, 候选 Permit2)` 和内部 `allowance(owner, token, 最终 spender)` 的 amount/expiration/nonce；可读代币单位/余额、固定区块、可选情报和分叉观察。每层失败分别保留未知。
- **仍未知：** 函数结构或 allowance 可读不认证 Permit2。代码/部署身份、domain 语义及未来消费仍未验证。
- **可扩展方向与边界：** 增加已验证部署/代码哈希、候选实现专用 domain 检查和消费交易适配器。未来消费仍需分析对应请求。

### 7. 常见 V2 兑换 / 限制卖出的证据

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 常见路由参数；满足条件时做隔离买卖往返实验。
- **取得后提供的字段/证据：** `method`, `path`, `amountIn`, `amountOutMin`, `recipient`, `deadline`；在支持时提供分叉中获得的代币、反向卖出结果、返回数量、gas 和资产变化；可取得的蜜罐、卖出税、黑名单和管理员观察。
- **仍未知：** 卖出失败可能源于余额、路由或流动性。往返损失不是纯税费；一次卖出成功也不保证以后能卖。
- **可扩展方向与边界：** 增加更多路径、已验证流动性/报价和多种数量/账户。未来黑名单、升级和交易排序不能完全预测。

### 8. 常见 V3 兑换

- **入口：** 支持的钱包交易实际交付时自动进入。
- **当前范围：** 八种规范 single/path、exact-input/exact-output，支持有界依赖式分叉买卖。
- **取得后提供的字段/证据：** path/fee/recipient、exact input/output 或 maximum input、价格/最小输出限制、可选 deadline；原买入 gas/费用/nonce；取得输出、实际输入扣减与衍生反向卖出。仅对代币出资且由实际 sender 接收的支持路径进行往返实验；原生币出资和路由专用 sender-sentinel 别名不再支持。
- **仍未知：** 不是官方池、可执行报价、未来可卖或 MEV 防护；不透明聚合器、不支持资金/接收人仍有缺口。
- **可扩展方向与边界：** 补充可信 quoter、规模/账户/流动性压力情景；不能保证未来排序、价格或管理员行为。

### 9. ERC-4626 结构的金库 / 份额

- **入口：** 支持的钱包交易实际交付时自动进入。
- **当前范围：** 当前接口及原交易实际分叉前后状态。
- **取得后提供的字段/证据：** 动作、数量/单位、receiver/owner；asset/totals/preview/max；原交易前后份额/底层余额、限制/allowance；同资产同单位差值，独立 phase 区块/hash/时间和缺失读取。
- **仍未知：** 接口不认证金库；不保证未来估值、偿付、捐赠/舍入安全、价格或赎回。
- **可扩展方向与边界：** 增加审查的协议/经济与价格/流动性情景；未来损失和退出仍不可保证。

### 10. 借贷 / 抵押

- **入口：** 支持的钱包交易实际交付时自动进入。
- **当前范围：** Aave 结构当前状态及原交易分叉后实际账户观察。
- **取得后提供的字段/证据：** asset/amount/onBehalfOf/rate/collateral；当前抵押/债务/可借/LTV/清算阈值/健康因子；原分叉前后相应读取、原始差值与操作后因子低于1的观察；固定 phase 快照和单位。
- **仍未知：** 完整仓位、未来价格、预言机真实性、利率、压力清算和未来偿付未核实；Base 单位不自动是 USD。
- **可扩展方向与边界：** 增加维护版本、可信价格/利率和明确压力假设；不能预测未来市场与预言机行为。

### 11. 质押 / 解除质押 / 提取奖励

- **入口：** 钱包提供交易时自动进入。
- **当前范围：** 部分常见函数和通用分叉检查。
- **取得后提供的字段/证据：** 候选 `stake`/`unstake`/`withdraw`/`getReward`/`claimReward` 方法；可读的原始数量和 receiver；部分控制权、固定区块、分叉中识别出的资产和有限调用。
- **仍未知：** 不自动读取锁定期、罚没、奖励公式和资金来源。`withdraw` 方法可能属于另一种协议。
- **可扩展方向与边界：** 增加已验证协议、仓位、锁定/退出条件和模拟适配器。不能承诺未来收益、不发生罚没或偿付能力。

### 12. 流动性 / 集中流动性仓位变更

- **入口：** 支持的钱包交易实际交付时自动进入。

## 5. Muse 输出、校验、修复与费用

只有 Muse 能提供新的数值分数。其输出包含 `score`（0–100 的整数或 null）、`assessment`、六个维度、`evidence_confidence`、`summary`、带引用的 reasons、`missing_data`、`suggested_action` 和 `honeypot`。后端记录模型/时间与有效 usage。维度是 `authority`、`exposure`、`execution`、`identity`、`protocol` 和 `deception`；每个恰好出现一次，包含定性评价并引用已有证据 ID。它们不是数值子分数，也不求平均。

数值是针对此请求、基于证据的未经校准风险指标。它不是损失概率、身份可信度分数或证据置信度百分比。没有固定数值分档、下限、累加点数、权重或规则/其他模型提供方的兜底分数。规则可以独立保留定性高风险信号。历史规则分数仍标为历史数据。

nonce/domain 断言检查覆盖摘要、原因、各维度、行动建议和缺失数据文本，包括条目索引、匹配/不匹配方向、否定及条件性建议；必须引用对应实际 RPC 观察，不能用无关引用代替验证。还会拒绝不存在/有歧义引用、重复/缺失维度、无依据确定性/蜜罐声明及相互矛盾的 null/unknown。自然语言校验只是部分防护，不证明每个句子都正确。评估范围记录此次请求实际未完成的检查与缺失证据；任何未知检查/缺口、模型发现的缺失、过旧/缺失/未来观察时间戳、公链区块来源/新鲜度失败或同高度冲突哈希都会阻止整体 low 或 strong 证据支持程度。完整 complete 与缺失列表继续显示；包字段为 assessment_scope，报告属性为 assessmentScope，策略名 observable-request-v1。允许的 low/strong 只针对可观察请求，不证明身份或未来安全。每个 low/review/high 维度须引用工具计划之外的非 unknown 观察。已知权限/敞口可以支持条件性数字，即使其他维度未知；全部维度无实际支持时不接受数值，缺少信誉也不证明恶意。

无效输出绝不在本地修改成某个分数。输出修复与 HTTP 500/502/503/504 暂时性错误共用一次额外请求，需要独立原子额度预留且至少剩余 5 秒。总计 50 秒、第二次最多 25 秒；修复复用相同证据、受控反馈和最多 20,000 字符的不可信先前输出。认证、额度、429、普通网络失败、超时、拒答、不完整封装和有效 null 不会自动重试。第二次仍无效就保持失败。只有每次尝试都有完整有效用量才合计 usage；HTTP 失败用量未知时省略合计。机器可读 failureKind/attempts/repaired 区分结果。

因此一次扫描最多可能消耗两次付费 API 尝试，失败也计数。默认整个后端的 `AI_DAILY_LIMIT` 是每 UTC 日 100 次。托管 `WALLETSHIELD_WALLET_DAILY_LIMIT` 默认每个已验证地址 20 次，网页/Snap 凭据共用。托管全局/钱包预算以原子方式预留；超过任一上限而拒绝时，两者都不扣配额。重启不重置 SQLite 计数。本地合成 AI 连接测试共用本地预算，在托管模式禁用。供应商美元额度和 RPC/情报配额另行计算。

没有 key、AI 关闭、配额拒绝、模型失败或诚实弃权时，都不会产生数值分数；证据和缺口仍保留。JSON/引用校验约束格式及部分声明，不证明每个句子或模型判断都正确。本地验收测试不意味着已有准确率/校准基准。

## 6. 哪些缺口可以改进？

30 个配置不是 30 个完整协议集成。承诺扩大覆盖前，应区分以下依赖：

| 依赖类别 | 可行扩展 | 仍存在的边界 |
| --- | --- | --- |
| 已配置 RPC 与经过测试的专用适配器 | 更多 allowance/仓位/封装读取、已知递归批次、操作后借贷情景、兑换路径和双链桥状态 | 不能认证协议、证明任意语义，或保证未来到账/偿付能力。 |
| 额外可信报价/价格/市场数据 | 预期输出、流动性、资产/LP/份额估值和压力假设 | 数据必须匹配资产/网络/时间；未来价格和排序仍不确定。 |
| 已验证源码/部署或声誉数据 | 构建/代码身份、真实系列/协议、管理员图和更广钓鱼/地址历史 | 名称、未命中或空代理槽都不是安全证明。 |
| 钱包/dApp/依赖方配合 | 暴露权限/UserOperation、原始哈希输入和登录 nonce/会话状态 | 提示词不能观察未传入的请求或存储。 |
| 链下服务或调查 | 业务身份、交易所内部信息、诈骗对话和设备/密钥泄露 | 需要独立集成/同意/隐私控制；链上数据不能确立全部链下事实。 |
| 单次快照在签名前无法证明的内容 | 把未来价格/流动性、排序、黑名单/升级、中继与隐藏效果作为情景探索 | 情景不能保证未来事件，也不能证明普遍不存在恶意行为。 |

| 缺口 | 实际改进 | 为何仍有边界 |
| --- | --- | --- |
| 缺少已知协议适配器 | 增加可信 ABI/源码/部署、读取和协议测试 | 相似函数名和欺骗性合约不能确立身份。 |
| 缺少实时数据 | 配置支持的 RPC/历史和情报；价格/身份服务需要另行开发接入 | 提供方可能收费、限流、失败、说谎或覆盖不足；模型参数不是实时数据库。 |
| 钱包未提供请求 | 增加明确的钱包/dApp SDK 或权限/UserOperation 集成 | 改提示词不能观察从未到达 Snap 的数据。 |
| 跨链到账 / 未来执行 | 读取两条链、桥证明/状态并模拟情景 | 未来共识、中继、排序、停机与状态变化尚未发生。 |
| 未来黑名单 / 升级 / 流动性撤出 | 检查当前控制权与压力情景 | 单个区块不能预测未来决定和价格。 |
| 链下诈骗 / 业务身份 | 增加已验证公共身份、网站与用户证据 | 正常代币和技术有效的转账也可能用于诈骗承诺。 |
| 原始哈希的原文 | 验证独立提供的原始消息/协议 | 单向 digest 不能唯一揭示原始授权。 |
| 任意合约语义 | 扩大已知解码、执行和形式化检查 | 自定义状态、动态调用、依赖和资源限制阻止普遍完整性。 |
| 分数校准 | 使用标注良性/恶意数据、独立测试集和误报/漏报测量 | AI 数值或合成测试通过不是测得的损失概率。 |
| 设备/密钥/交易所被攻破 | 集成适合的外部产品 | 单次签名前请求不能诊断恶意软件、既往密钥泄露或私有交易所账本。 |
| 非 EVM 链 / 其他钱包 | 实现其交易/签名/权限格式和工具 | 不能把 EVM 规则换个标签就称为支持 Bitcoin/Solana。 |
| 强制阻止 / 持续签后监控 | 超出当前建议型产品范围 | 用户仍负责钱包决定；旧兼容代码不是已启用的监控产品。 |

## 7. 运行、认证与发布

安装、配置、启动、停止、测试和发布命令见[中文 README](../README.zh-CN.md)及 [README.md](../README.md)；操作流程见[中文使用手册](USER-MANUAL-zh.md)及[英文使用手册](USER-MANUAL.md)。默认开发 Snap 使用本地 8080 文件服务与 8787 直连 API；浏览器 API 请求经网页代理。托管构建使用一个编译进包的 HTTPS origin/npm ID，并由配置的 HTTPS 代理转发到回环后端。打包不等于发布、注册或生产认证。

配对会先验证后端接受，再保存 Snap 状态。后续经过认证的健康检查区分“已安装”和“配对可用”。托管登录使用 5 分钟、一次性的精确消息挑战，经 EOA 或支持的已部署 ERC-1271 策略核对；网页 bearer 有效 8 小时、仅存内存；另有绑定地址的独立 30 天 Snap bearer。所有者可撤销该地址全部网页与 Snap 凭据。报告/证据访问及配额按已验证地址隔离。采集渠道记录凭据来源，不是 Snap 执行的密码学证明。托管模式不注册本地 lab/funding/legacy/demo/monitor 路由；任意 Origin 请求头都不能替代认证。

Snap 凭据签发使用 SQLite 原子、持久化限流：每分钟每地址 4 次、服务端观察 IP 12 次、全局 60 次；每地址最多 4 个活动凭据，全局最多 8192 个。成功重载只轮换该 owner 最早到期的凭据，拒绝返回 429/Retry-After、不改变已有凭据也不扣签发计数；过期和旧限流记录使用索引清理。历史与详情在账户/provider/断开或失败重载后清空；取消/过时异步响应被丢弃，当前所有者列表中消失的选择清空。本地模式的同机历史仍是共享工作台历史，不是托管模式的用户隔离。

含唯一 nonce 的中性 `personal_sign` 消息，可在不消耗 gas、不授予资产权限的情况下测试真实钱包/Snap 入口。页面把精确匹配的请求与已配对 Snap 报告关联。生成的测试签名留在浏览器；未签名消息/报告到达后端。这与托管登录不同：登录时明确请求的认证签名会发送去验证，但不存储。实际资产交易仍由用户通过钱包/dApp 发起。

## 托管隐私、上游预算与证据强化

**Sign out all sessions and revoke pairing** 会以原子操作撤销当前已验证地址的全部网页/Snap 凭据和未完成登录挑战，其他钱包不变。恢复使用须重新验证与配对。**Delete my stored reports** 先要求明确确认，只删除该地址拥有的报告，并撤销该地址全部凭据；使用额度不清零。每次托管报告插入/更新都会在同一 SQLite 事务内校验凭据仍有效且归属正确，撤销后的进行中请求不能把报告写回来。已发送给 Meta/RPC/情报服务的请求无法因删除报告而撤回或退款。

这里的删除是 SQLite **逻辑行删除**，不保证 WAL 页、磁盘、备份或第三方日志中的历史字节被法证擦除。应用不加密数据库。自动保留默认关闭；运营者可在后端 `.local/service.env` 或进程环境配置以下非密钥项：

```dotenv
WALLETSHIELD_SCAN_WALLET_DAILY_LIMIT=100
WALLETSHIELD_SCAN_IP_DAILY_LIMIT=300
WALLETSHIELD_SCAN_GLOBAL_DAILY_LIMIT=1000
WALLETSHIELD_REPORT_RETENTION_DAYS=0
```

证据/RPC/分叉扫描预算独立于模型调用预算：托管扫描在**采集之前**原子预留六个范围（每分钟每钱包 8 次、服务端观察 IP 16 次、全局 60 次，另有以上可配置 UTC 日上限）。任一范围耗尽就拒绝扫描，不扣其他范围，不启动采集器。计数持久化，重启不重置；拒绝/未完成检查不产生兜底分数。模型调用仍有独立限额。这是初始容量策略，不是公众规模吞吐或可用性保证；网络连通探测仍有自己的限额。可配置日上限范围：每钱包 1–10,000、每 IP 1–100,000、全局 1–1,000,000。

保留天数 `0` 不删除已有数据。显式设置 1–3650 天时，每次启动及之后每分钟最多清理 100 份已过期且有托管所有者映射的报告，积压可能需要多批；年龄按报告创建时间计算。无所有者映射的本地历史、使用额度、其他应用状态和第三方副本不由该策略删除。

公链区块来源与采集时间分开记录。`quality.blockFreshness` 标出 RPC/隔离分叉区块时间超过 300 秒、未来超过 30 秒、缺少区块时间/hash 或链身份未验证的观察；这些缺口会阻止整体 `low` 和 `strong` 证据支持程度，不是评分权重。合成演示与本地链 31337 不按公链区块年龄限制，因为本地时钟可能人为设置；观察时间诊断另算，新近区块也不证明没有重组或节点不一致。

Muse 新增接收 `evidence_admissibility`（各维度可由哪些实际观察支持）与 `claim_support`（有界基本调用/分叉执行/分叉卖出的支持）。真实但不相关的引用不能支撑该维度。代币元数据/开源状态或卖出风险标记为零，不能单独支撑身份、诱导或权限结论；实际控制权标记可支持权限，卖出/税费观察可支持敞口/协议，负面身份断言须有绑定请求/链的已识别风险观察。后端对所有展示文字检查无依据的“官方身份”、绝对安全、未来执行/卖出保证与事实性美元损失断言，同时保留明确未知与条件建议。基本调用不是交易上链，分叉结果不是公网执行或未来保证。这些只是部分自然语言防护，不是形式证明或独立准确率/校准基准；本轮新增检查采用离线对抗样本，不证明当前线上 Muse 的准确率。模型成功响应流式限制为 150,000 字节，错误响应为 16,000 字节，超限会取消读取，拒绝无效 UTF-8；不会把原始供应商错误文本作为用户建议。资源限制不证明模型结论真实。

GoPlus 仍需显式开启。它从已识别的外层/路径/Permit2/批量字段中最多选八个代币与八个交易对手，不把桥的远端 token 或 delegatecall 目标直接当作本链代币。每轮最多十八个网络请求、四路并发、单请求 1.8 秒、总共 7.5 秒；响应缓存三十秒（最多 256 项），支持链列表缓存一小时。结果带 `fetchedAt`、`cacheHit`、`cacheAgeMs`、`cacheTtlMs`、`providerAsOf:null`、`freshnessVerified:false`；刚取得不表示知道供应商数据的实际日期。缺失标记、闭源/代理导致的遗漏、未查询/截断候选与未命中均是边界，参见 [GoPlus 官方响应说明](https://docs.gopluslabs.io/reference/response-details)。

代币出资的规范 V3 single/path、exact-input/exact-output 保留有界依赖式分叉买卖适配器。原买入保留已有执行字段，衍生卖出按实际输入扣减和取得输出计算。移除部署绑定后，V3 原生币出资往返实验及路由专用 sender-sentinel 接收人别名不再支持；适用时仍可进行原交易通用模拟。候选池/factory 关联、tick/range 和有效流动性仅是观察，不认证官方池、报价或未来退出。不透明聚合器、不支持的资金/接收人及未来排序仍有缺口。钱包目录现为 67 个代表性案例；移除前的历史验收结果不认证当前缩小后的范围。

自动入口仍取决于钱包实际交付。MetaMask 当前仅显示 Critical 严重级别的消息洞察，并在进入 Sign 后展示；交易洞察有独立入口，参见 [官方入口说明](https://docs.metamask.io/snaps/reference/entry-points/)。权限、会话、UserOperation 等仍需显式 API 或配合的 dApp SDK 接入，不安装全局钱包拦截。托管登录支持 EOA 恢复及支持范围内已部署合约的 ERC-1271 精确登录消息核对；未部署/ERC-6492 和不支持的策略仍不可用。公开上线仍需真实域名/TLS、目标 Snap 发布与分发、浏览器钱包验收、安全备份恢复以及负载/故障测试。

## 8. 隐私与证据流向

钱包/网页 → 已配置后端 → 已配置 RPC 和已启用情报 → 有界证据包 → Meta Responses API → 后端报告 → 网页/Snap。

启用时，所配置后端会向 Meta Muse Wonder 发送必要证据。它不索要助记词、私钥或已生成的资产签名。消息预览和解码请求字段仍可能包含私人信息；托管登录使用单独、明确请求的签名。

- Meta/RPC key 只留在后端，不进入浏览器/Snap 配置或 AI 证据。运行时部署设置是公开、非秘密值。
- 后端在 SQLite 保存完整未签名请求、证据和输出；托管模式将其保存在运营方服务器。凭据以哈希保存。数据库未加密，也提供可选有界保留策略，默认关闭。
- 模型输入省略完整 calldata/历史，但可能包含私人消息预览和解码请求字段。修复会重发相同证据及有限的先前输出。过滤不是通用秘密检测器。
- RPC 可看到读取和分叉所需的地址/调用数据。启用 GoPlus 时，它可收到规范化公开 origin、最多八个代币候选和八个明确交易对手。当前未配置自动全站抓取或完整钱包历史导入。
- 模型请求使用 `store:false`。这个选项不是对提供方日志或保留期限的普遍保证；请查看适用的提供方/服务政策。
- Snap 优先显示最多 24 条证据、6 行请求参数和 6 条缺失检查摘要。工作台仍保存完整证据。显示条数限制不证明未显示的检查已通过。

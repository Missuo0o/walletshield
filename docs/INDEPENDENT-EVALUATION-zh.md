# 独立标注风险评估

项目新增了**只读的外部标注评估工具**，补上了独立准确性评估的工具流程。它不会自行编造独立标签，也不代表现在已经获得一个可信准确率。原有合成样本继续验证解析、证据校验与回归行为，不充当独立基准。

该命令不调用 Muse、不调用 RPC、不读取 `.local` 或报告数据库，不修改输入文件。它仅比较之前保存的模型结果与冻结的外部标签，不修改生产评分，不加固定权重或备用分数。

## 标签的确切含义

目前只支持 `expert-adverse-risk`：由独立审核人员根据**该时间点的未签名请求和实际证据**，按照明确政策判断安全风险。

| 标签 | 含义 |
| --- | --- |
| `adverse` | 证据支持存在明确的不利安全风险，不表示未来损失的概率。 |
| `benign` | 符合政策中的良性/对照情境，不保证未来永远安全。 |
| `indeterminate` | 证据不足以确定二分类；不自动将弃权或数字评分视为正确。 |

例如，被独立证据确认恶意的 spender 请求可以根据明确政策标为风险；**不能仅因无限授权就一律标为恶意，也不能仅因金额小就标为安全**。模型的 `review` 表示暂缓二分类判断，不是攻击标签或损失事件。`labelBasis` 区分专家审核与已验证事件；已知事件必须对应同一请求、同一时点，并说明样本选择。不同目标（如未来一段时间是否实际损失）需要另行制定评估方案。

## 使用流程

1. 获取有授权的、去标识化的独立审核样本，包含风险、良性和无法确定的案例；记录标签政策、采样方式、来源、链与协议分布。标签不能来自被评估 Muse 的分数。
2. 私下保存冻结的完整证据包，以 `evidenceSha256` 标识。之后传给模型的必须是同一份冻结证据，不能重新读取新的区块后仍沿用旧标签。
3. 记录审核人、角色、审核时间、理由及来源引用；分歧按照政策解决，未解决的可标为 `indeterminate`。
4. 分离 `development` 和 `holdout`。同一事件或相关变体共用 `groupId`，不能跨开发集与留出集；同一证据哈希也不能跨集。任何用于调提示词的样本必须标记 `usedForPromptTuning: true`，不得留在留出集。
5. 先冻结标签，再生成结果。计算整个标签清单的哈希：

```bash
npm run --silent evaluate:independent -- --labels=/private/path/labels.json --hash-only
```

6. 固定模型与版本、提示词哈希、采集器版本。每个案例保存预先约定的一次结果，包括正常数字、弃权、错误和无需评分。**不能挑选重试中最好的结果**；重复实验用独立的冻结运行文件。保留原始请求/重试成本日志。
7. 结果文件中的 `labelsSha256` 必须匹配冻结标签；逐条证据哈希与时间也必须一致。运行：

```bash
npm run --silent evaluate:independent -- \
  --labels=/private/path/labels.json \
  --predictions=/private/path/predictions.json \
  > /private/path/evaluation-run-001.json
```

工具拒绝未知字段、重复案例/预测、标签哈希变动、证据包变动、不合理时间、声明用于调参的留出案例，以及组或相同证据跨集。每个 JSON 输入限制 16 MB。结果仅写到标准输出，建议每次重定向到新文件。

结构定义见 [`independent-evaluation.ts`](../src/evaluation/independent-evaluation.ts)，可运行的**合成格式示例**在 [`evaluation/`](evaluation/)。示例中的审核人与预测都是虚构的测试数据，不代表真实准确率。获得真实独立标注后才可使用 `provenance: "externally-reviewed"`。

## 看什么指标

开发集和留出集分别报告，不合并成一个漂亮数字；提供案例数和声明的组数，不将相关案例假装成独立统计样本。

| 指标 | 解释 |
| --- | --- |
| 结果数量 | 数字、有效弃权、错误、无需评分、缺失分别统计；错误/缺失绝不算正确。 |
| 数字覆盖率 | 得到数字的案例占比；另有仅对二分类标签的覆盖率。 |
| 二分类决策覆盖率 | 模型给 `high` 或 `low` 的数量占全部二分类案例的比例；`review` 属于暂缓判断。 |
| 选择性准确率等 | 仅在已决定的结果上，将 `high` 视为风险、`low` 视为良性，统计准确率、精确率、召回率、误报率，保留分子分母；不用固定数字阈值。 |
| 全案例指标 | 风险正确标记率、风险误判低风险率、良性误报高风险率均保留全部相关案例在分母中；需与缺失/弃权/暂缓比例一起看，不能只看一个低漏报率。 |
| AUROC 排序 | 在已出数字且标签明确的样本中，高分能否将风险排在良性之前；同分计半分。缺少任一类别时不计算；不包含失败、弃权、未知标签，不能冒充全样本表现。 |
| 未知标签 | 单独记录其数字与弃权结果，不自动给正确性奖励。 |

**仍不进行概率校准。** Muse 的 0–100 是风险指标，不是明确定义的损失事件概率。直接除以 100 计算 Brier 分数或概率可靠性分箱，会制造错误含义。独立标签可评估排序/分类并指导改进；若将来需要预测损失概率，必须另有对应时间窗口、真实结果标签、适当采样和未参与拟合的留出集。

## 为什么不能直接宣布“已校准”

代码只能检查输入记录是否相符，不能证明审核人独立、时间真实、模型从未见过留出样本、来源标签正确，或者模型确实收到记录哈希对应的数据包。外部审核模式因此明确显示“外部审核/留出声明尚未独立证明”。哈希可发现与结果清单不一致的修改，但不是数字签名、可信时间戳或防篡改存档。

真正的准确率仍需要独立审核人员、合理的采样和按照上述方案收集的冻结预测。本次完成的是可复现评估流程、指标和确定性测试，没有把项目自行生成的样本冒充独立结果。

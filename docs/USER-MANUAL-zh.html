最新修复与验证见2026 年 10 月 24 日修复报告，涵盖声明校验、RPC 快照一致性、本地钱包有界等待和托管会话界面生命周期。此前的订单与 trace 修复说明保留为带日期历史记录，不用其结果作为本轮验证计数。

此前可靠性与 trace 改进说明评分分类、只读豁免、精简事实选择、暂时性错误恢复和专用 trace 配置。之前的完整验证保留原模型/钱包观察，历史结果不改写。

更新后点击 Reload and pair Snap，确保 MetaMask 使用重建代码。模型完成分析也可能因证据不足而不提供数字；无效输出会被拒绝，错误提示说明支持识别的校验问题。重要检查未完成时，即使有 Muse 数字，综合标题也可以是 Unable to assess：模型指标与完整性是不同概念。交易传输的超时覆盖正文解析，响应正文停滞时会报错，不会无限等待。

本手册说明当前英文界面以及已经实现的本地和托管使用流程。WalletShield 在你通过钱包作出决定之前，对尚未签名的 EVM 请求提供建议。它不能保证安全、强制拒绝、代你签名、追回资产，也不会持续监控已签名请求。

中文 README 提供配置与开发参考；中文能力覆盖指南 列出全部 30 个分析类别（profile）的准确提取字段、工具、缺失检查和可扩展方向。当前本地实验室有 67 个代表性案例：51 个交易请求和 16 个消息签名请求，涉及 30 个分析类别中的 25 个。这些案例不是检测准确率基准。本手册对应英文使用手册；当前界面及新生成的说明为英文，旧报告保留原记录语言。

当前覆盖范围对照表区分代表性实现、部分证据、手动入口和未覆盖内容，并记录本轮正确性与依赖修复。

当前检查使用钱包提供的未签名请求、来源 origin/网络元数据，以及成功取得的 RPC、情报和模拟证据。Muse 评价可观察请求信号，包括支持范围内的来源、消息和请求不一致。链/provider/执行上下文指技术观察。历史报告与验收文件保留原始记录，不被删除或改写。

快照、声明与界面防护

  • pinnedRpc 优先使用 EIP-1898 区块哈希选择器及 requireCanonical: true。只有提供方返回无效参数错误时，该方法才回退到区块号。区块号读取在前后核对链和完整区块头，整个关联采集组结束时再次核对原链、高度、哈希和时间戳；其他已确认状态的区块号采集组也进行前后核对。区块头缺失、畸形、变化或无法复核时，会丢弃该组 RPC 状态值和由其推导的结论，单独保留请求/密码学证据并记录缺口。
  • 某个合约接口失败时，只有关联快照通过一致性核对，其他独立取得的事实才会保留。快照无法核实时，不会把已读成功的值继续挂在旧哈希下。不同采集器仍可能使用不同区块，pending nonce 仍是明确未固定的节点视图，分叉执行也有独立状态。这些核对不构成全局原子快照，不证明 RPC 诚实，也不保证未来执行。
  • 确定性校验按声明所在的分句检查。“你应该批准”或另一句谨慎措辞，不能豁免相邻的无依据官方身份、安全、未来执行/卖出或事实性美元损失断言。真实的不确定表述和条件式核实建议仍允许。这是有界语言防护，不是每句话或分数正确的证明。
  • 本地准备/清理捕获同一个账户和 provider，钱包动作共用 120 秒期限，账户/链读取最多 5 秒，钱包提示最多 60 秒。超时后网页解除等待，不自动重发切换/添加网络请求。仅未知本地网络可用链 31337 和回环 RPC 添加一次，随后仍须确认链状态。资产显示遇到超时或已有待处理请求时停止继续弹窗。资金准备成功与钱包显示分开：拒绝、不支持或待处理的显示请求不会撤销已准备资产。请打开 MetaMask 自行批准或取消剩余提示；网页不能替钱包取消。资产清单另行刷新。
  • 托管网页登录有效 8 小时，Snap 配对使用独立的 30 天期限。已知到期会更新对应界面；网页到期清除网页验证身份和私有历史，不把独立 Snap 凭据一并视为过期。受保护网页接口返回匹配的 401 时，只作废该请求实际携带的凭据，且在解析 JSON 前处理；旧请求的拒绝不会清除较新的登录。范围不匹配的 403 保留凭据。浏览器恢复焦点或可见时再次检查到期。尚未收到的撤销信息仍须通过认证响应或健康检查发现。

当前证据与接入新增能力

Muse 以 walletshield-selection-v1 选择精确事实 ID，后端解析并保存为 walletshield-facts-v1，保留每个理由/维度引用。历史完整事实格式仍可读，语义校验仍保留。后端不证明每个供应商响应或自然语言句子真实；数字只由 Muse 给出，没有固定权重、下限或兜底。

界面分别显示证据不足、模型输出被拒绝、连接失败、分析中、未运行和 Not applicable · Read-only query。最后一种仅用于参数严格验证的有限查询，不消耗模型额度，也不检查隐私和返回数据安全；未知扩展不会自动豁免。未来独立准确率测量见独立评估流程，附带合成格式示例不代表真实准确率。

后端部署登记/代码匹配、USD 参考价格源和维护式两链桥接路线核对已移除。已有 .local/registry.json 不再读取。基础交易/授权/签名解析、配置的 RPC 状态、部分 V2 路径（含已有原生币路径）、代币出资 V3 与通用分叉模拟、可选 GoPlus 和 Muse 评分保留。ENABLE_SOURCE_VERIFICATION=1 仍独立启用有界 Sourcify 源码匹配观察；它不是官方部署登记或代码审计。

有界证据包括 Seaport 签入承诺、Permit2 witness 外层承诺、UserOperation 参数/代码/费用观察、EIP-7702 元组密码学/有条件状态、原始分叉交易前后部分权限/金库/借贷状态、代币出资的 V3 路线实验和候选池状态。规范 Seaport 结构订单会在固定区块读取候选 information()、counter 及取消/填充 getter。counter/status 返回值保持 unknown，不验证真实 nonce、填充或取消语义。域哈希比较可得到相同或不同，但不认证 verifier 身份，也不推断直接 verifier 的资产授权。依赖可信部署身份的订单语义与 EntryPoint keyed nonce/deposit 检查仍不提供。dApp 包装器须主动接入，不是全局钱包拦截；托管 ERC-1271 只验证本次登录，不验证未来资产签名。

Wallet and network 页面提供有界只读 RPC 能力观察：固定区块调用、一次历史余额和固定 trace 探测。成功不是完整 archive/trace 保证。源码核对仍是独立可选后端配置，公网页面不显示其状态。Public networks 的切换按钮通过选定钱包 provider 直接调用 wallet_switchEthereumChain，不调用接入 SDK、风险扫描或 Muse，由钱包处理确认。

npm run evaluate:ai 默认运行固定哈希的合成校验器检查，不请求模型/RPC，不代表在线 Muse 准确率。付费评估必须显式指定 --live --confirm-paid、案例和调用预算，不会自动运行。

2. 本地安装与启动

使用 Node.js 24.x、npm，以及安装了 MetaMask Flask 的桌面浏览器。使用专门的开发账户。应用内嵌浏览器可能没有钱包扩展。

在项目目录执行：

node --version
npm ci
npm run demo

该命令构建网页和 Snap，启动全新的 Anvil 链，部署本地测试合约，并启动以下回环服务：

服务 地址 需要保持运行的用途
网页 http://127.0.0.1:5173 工作台和浏览器 API 代理
后端 http://127.0.0.1:8787 分析、取证、配对、认证及 SQLite 历史
开发 Snap 文件服务 http://127.0.0.1:8080 安装或重新加载本地 Snap
Anvil，链 31337 http://127.0.0.1:8545 本地余额、测试合约交易和实验室测试

在装有 Flask 的浏览器中打开 http://127.0.0.1:5173。网页把 /api 代理到 8787 端口；Snap 直接访问 http://127.0.0.1:8787/api，其带认证、来自不透明来源（opaque origin）的预检请求必须能够到达后端。5173 不是当前 Snap 的 API 端点。

保持启动命令所在终端打开；在该终端按 Ctrl+C 可停止本次启动器拥有的服务。第二次启动发现端口被占用时会拒绝启动，先停止之前的 WalletShield 会话。释放端口前确认进程归属，不要随意结束其他程序。

每次重新运行 demo 都会重置内存中的本地链，之前的本地授权、余额、头寸和回执会消失；SQLite 报告继续保留。重启后重新准备资产。旧报告是历史观察，不描述新链的当前状态。

开发时，npm run dev 只启动后端、网页和 Snap 文件服务，不创建链，API 进程也不会监听代码变化并自动重启。按照 README 的多终端顺序，依次使用 npm run chain、npm run deploy:local、npm run build 和 npm run dev。修改 Snap 后须重新构建，再重新加载和配对。

3. 配置数据与可选 AI

没有模型密钥也能运行本地钱包请求。Muse 未启用、未配置或未成功完成有效分析时，报告只显示证据和缺口，不显示数值分数。

按需创建 .local/，以 .env.example 为配置参考，并保留已有设置。项目根目录下任意命名的 .env 文件不会自动加载。

配置 本地文件 用途
MODEL_API_KEY .local/meta.env Meta Model API 凭据，仅供后端使用
ENABLE_META_AI=1 .local/meta.env 允许模型调用；设为 0 则禁用
AI_DAILY_LIMIT=100 .local/meta.env 整个后端每个 UTC 日的模型尝试上限，可设为 1–1000
INFURA_API_KEY .local/rpc.env 为后端生成 Ethereum 主网和 Sepolia RPC 端点；与 Meta 密钥不同
RPC_<CHAIN_ID>_URL .local/rpc.env 该链明确配置的可信端点，优先于生成的端点
ENABLE_FORK_SIMULATION=1 .local/rpc.env RPC 和历史状态支持时，选择启用临时本地分叉执行
ENABLE_EXTERNAL_LOOKUPS=1，以及可选的 GOPLUS_TOKEN .local/rpc.env 选择启用 GoPlus 信誉和代币观察

不要将凭据放入浏览器输入框、Snap 配置、源码或请求 JSON。.local/ 与凭据 .env 文件被 Git 忽略；示例文件只含占位符。显式进程环境变量优先。服务会逐请求重新读取配置文件；若修改的是进程环境变量，则需要重启。链 31337 始终固定到本项目拥有的本地节点。公网 RPC URL 必须使用 HTTPS，回环 HTTP 除外；含内嵌用户名或密码的 URL 会被拒绝。

Muse 固定使用 https://api.meta.ai/v1/responses 上的 muse-wonder-1.0，不使用 OpenAI 凭据，也没有切换其他供应商的回退路径。“已配置”只表示配置存在，不证明实时连通；只有某次已完成且通过验证的响应，才能证明该次调用成功。

每次初始调用预留一次尝试额度，失败也计数。允许的输出校验修复调用会再预留一次。后端默认每天最多 100 次；托管模式还默认限制每个已验证身份每天 20 次，该身份的网页和 Snap 会话共用。托管额度以原子方式同时检查两个上限：任意一个拒绝时，两个计数都不扣减，也不发起模型调用。这些是尝试次数上限，不是金额预算；RPC、Infura 和 GoPlus 的限额与计费独立。

README 中本地合成 AI 连通性测试命令会主动调用 Meta，可能产生费用。安装、离线测试或无评分取证不需要运行该命令。托管模式没有此测试路由。无论 ENABLE_MONITOR 如何设置，定时签名后监控都保持禁用。

4. 连接钱包并验证 Snap

  1. 在 Choose wallet 中选择目标钱包扩展。支持时，EIP-6963 发现机制可区分多个钱包提供者。选择普通 MetaMask 不会使其具备安装本地开发 Snap 的能力；该流程使用 Flask。
  2. 打开 Wallet setup，点击 Connect wallet。核对网页和钱包显示的账户。WalletShield 不索取助记词或私钥。
  3. 点击 Install and pair Snap，在钱包中批准明确列出的权限。本地 Snap ID 为 local:http://127.0.0.1:8080。
  4. 等待安装、获取配对凭据、连接后端和健康验证各阶段完成。Snap 在保存凭据前先检查后端是否接受，随后网页发起新的带认证健康检查。仅安装 Snap 不代表配对成功。
  5. 重新构建或修复过期安装后，刷新网页并使用 Reload and pair Snap。再次核对提供者和账户。

以 Snap installation incomplete 开头的错误属于安装阶段。Snap installed; pairing credentials unavailable、Snap installed; backend connection incomplete、Snap installed; pairing verification failed 分别指向后续的凭据、后端连接和配对验证阶段。用户取消仍然是取消，不代表扩展不兼容。本地构建时确认扩展可访问 8080 和 8787 端口；旧 bundle 可能仍指向 Vite 的 5173 端口，需要重新构建和加载。

Snap 权限允许交易和消息洞察、网络访问、主页显示、状态存储、配套网站 RPC，以及只读的钱包提供者观察。它们不会形成覆盖所有钱包权限、会话、智能账户请求或网络变更的统一拦截入口。

5. 运行本地钱包测试

  1. 在 Wallet setup 点击 Switch to local chain and prepare assets。在钱包中批准添加或切换至 WalletShield Local，链 31337（0x7a69）。准备流程在写入测试状态前，会验证本项目拥有的 Anvil 节点和测试合约代码。
  2. 打开 Local wallet lab 查看链上资产。准备流程补足测试 ETH、TEST-USD、LAB-USD、LAB-Q、LAB-BLOCK，并准备测试 ERC-721/1155 资产；不会自动授权路由器，也不会自动建立金库、借贷或质押头寸。
  3. 选择 Operation category 和案例，阅读 Prerequisites（前提条件）与 Test limitations（测试局限）。每一项必要授权或存入操作都要在钱包中单独完成。包装或解包案例所需的包装资产，通过本地包装操作取得。
  4. 点击 Request a test transaction 或 Request a test signature。在钱包中检查账户、链、接收方、金额、权限和消息，阅读 WalletShield 洞察及未完成检查。MetaMask 决定何时展示消息洞察，有时需要先进入 Sign 步骤。
  5. 在钱包中确认或取消。建议从 Unlimited approval 开始，阅读洞察后取消，再比较有限授权和撤销。请求即使被取消，也可能已经生成完整的签名前报告。
  6. 查看 Wallet test history。Wallet outcome（钱包结果）和 Snap delivery（Snap 送达）是两个独立记录。Not observed 表示未记录到匹配的 Snap 提交；返回签名、仅 API 生成的报告或成功的节点测试都不能替代该观察。
  7. 打开 Check history 查看报告与完整证据，必要时刷新列表。已有报告可能来自此前的链状态或实现版本。

准备完成后，网页自动使用 wallet_watchAsset 请求钱包显示五种已知 ERC-20（包括余额为零的 WLAB）与当前拥有的测试 NFT，请确认钱包提示。拒绝显示或钱包不支持 NFT 导入不会撤销链上资产准备；校验后的链上清单仍是余额依据。MetaMask 扩展中的 NFT 导入属于实验性功能。测试 ETH 无需导入。NFT 和头寸可能需要对应操作才能取得或补充。已有余额高于补足目标时，准备流程会保留较高余额。本地路由价格、金库份额、借贷行为、跨链记录和控制测试合约均为简化模型，不是官方协议部署或真实金融模型。LAB-BLOCK 刻意限制卖出，用于测试相关证据路径。

Clear local test assets 仅清空所选账户在链 31337 上已知测试合约的钱包余额，请先阅读英文确认提示。后端验证 Anvil 和合约代码，销毁或丢弃测试代币、解包装 WLAB、将测试 NFT 转至固定丢弃地址，并将该账户的本地测试 ETH 设为零。NFT 单项授权随转移清除；ERC-20/操作员授权、协议仓位、控制状态和历史保留。未知代币合约及钱包显示项不变，不重置整条链，托管模式不可用。若中途失败，已完成步骤可能保留，应刷新余额后再重试。再次准备即可补充测试资产。

实验室生成的签名在浏览器中完成格式检查后即丢弃，不上传、不持久化，也不提交用于资产操作。未签名消息仍会到达后端，其受长度限制的预览可能发送给 Muse。

可选账户与签名变体测试

新增 8 个 Smart-account fixture 交易测试 threshold 降低、module 标记开/关、guard 设置/移除、fallback 设置/移除和 CALL 封装。已有本地部署请明确运行 npm run deploy:lab，只补充可选 LabAccount 后，再点击 Prepare local test assets。部署保留原测试合约地址/状态；准备资产会将可选账户重置给当前测试者。移除类案例先完成对应设置。

这是 owner 可直接调用的本地接口模型：无论显示 threshold 为多少，任一列出的 owner 都能直接调用。它不是生产多签；module/guard/fallback 只是标记，不实施真实约束。封装仅接受 CALL、空 signatures、零退款参数，故意拒绝 DELEGATECALL；不会修改真实智能钱包权限。

另有 dai-allow、dai-revoke、erc3009-transfer、erc3009-receive 四个签名案例，使用现有 LAB-USD domain 发起真实钱包消息，以测格式和字段提取。LabToken 不实现 DAI/ERC-3009 消费方法，也没有 ERC-3009 authorizationState getter；缺失状态/消费证据是预期边界。签名本身不消费消息、不改 allowance、不转币，生成签名仍在浏览器丢弃。

NFT 订单与自定义未解析案例

钱包实验室现在区分 NFT order components（order）和 Custom unresolved order（order-custom）。前者按当前拥有的本地 NFT、签入的对价接收人、时间窗、唯一 salt 和专用 verifier counter 构造完整规范 OrderComponents。只读 LabOrderVerifier 仅暴露 domain separator、information、counter 和初始状态；它不是 Seaport，不能履约、取消、消费或验证签名。已有实验室需明确运行 npm run deploy:lab，补充可选 orders，不替换旧合约地址/状态，然后点击 Prepare local test assets。若 NFT 已转出，请重新准备资产。自定义案例保留未赋予协议含义的已签入标量字段，故意保持协议未知；没有实质性不利证据支持评分时，无数字是预期结果。两个案例都发起真实钱包签名请求，生成签名仍在浏览器丢弃。

6. 使用公网和自己的账户

Public networks 用于查询公网数据并检查实际 Snap 送达。先使用 Sepolia 和专用测试账户。主网可能持有真实资产，本地 Flask 开发钱包不应存放这些资产。

  1. 配置可信的后端 RPC。有效 Infura 密钥提供 Sepolia（11155111）和 Ethereum 主网（1）端点；其他列出的链需要显式配置可信端点。
  2. 连接目标提供者和账户。本地模式的连通性检查可以不提供账户；托管模式必须先验证身份。
  3. 在 Backend query network (does not switch your wallet) 选择后端查询网络，再点击 Check RPC and account state。后端验证返回的链 ID，读取区块和时间，以及可选的原生币余额与代码；它会区分可识别的委托指示代码和普通无代码账户。结果可复用 15 秒。
  4. 对比所选后端查询网络与 Current wallet network。选择查询网络不会切换钱包。确实需要切换时才点击 Switch wallet to this network。按钮直接请求 wallet_switchEthereumChain，不经过 SDK 分析或风险扫描、不调用 Muse；在钱包中确认或取消。该网络必须已添加到钱包；否则通过可信官方资料添加后重试。后端密钥和 RPC URL 不会提供给钱包用于网络配置。
  5. 安装和配对所配置的 Snap，验证健康状态，再点击 Test the wallet signing insight。它生成唯一的普通 personal_sign 消息，含网站、账户、所选网络、nonce、时间戳和用途，不消耗 gas，也不授予资产操作权。
  6. 阅读完整消息和洞察后决定签名或取消。网页用完全一致的消息匹配后端 paired-snap 报告；只有签名响应不能通过送达检查。生成的测试签名留在浏览器，未签名消息和报告保存在后端。启用的 Muse 分析会消耗相应尝试额度。
  7. 真实资产请求从对应外部 dApp 发起。逐项阅读洞察并在钱包中决定。公网页面不构造转账、授权或充值交易。

切换请求会立即发送。页面最多等待钱包回复 60 秒，随后短暂核对钱包报告的链，再显示成功。如提示已有待处理请求，请打开选定钱包处理原有弹窗。页面超时不会取消钱包弹窗，重试前先检查钱包。未知网络须依据可信资料手动添加。

RPC 探测、中性消息洞察测试和托管登录是三个不同操作。RPC 连通不等于评估了账户或接收方；中性消息不会登录服务；托管登录也没有测试所有资产分析路径。配对健康只证明带认证的后端可达，不保证安全或未来每个请求都能送达。

钱包连接、后端 RPC 和协议适配也有不同职责。 MetaMask/Flask 连接网页与用户账户、展示请求并由用户决定签名；Infura 或显式 RPC 给后端提供相应链的状态；协议适配器负责对特定 ABI、版本和方法进行有边界的解析与检查。连接钱包不会自动配置后端 RPC；RPC 可用也不会自动认证协议身份或补齐所有协议语义。

交易内部调用追踪

设置 ENABLE_FORK_SIMULATION=1 后，现有临时 Anvil 分叉还会在本地执行之前，对源基础区块尝试有界 debug_traceCall，并在前后核对源节点和子分叉的链/区块出处。只要 Anvil、已配置 RPC 及所需历史状态可用，即使公网 RPC 没有 trace 方法，也可能取得 call_trace_fork，无需另购专用 trace 服务。不会向上游发送交易。提供方 call_trace 和隔离分叉 call_trace_fork 分别保留出处；主端点能力面板显示 trace 失败，不会抹去成功的分叉追踪。两者都不等于完整资产清单、签名消费测试或未来执行保证。追踪针对未签名交易；普通或类型化消息签名不会因此作为交易执行，仍需要对应协议证据。

7. 阅读证据和 AI 评估

参考分数前，先阅读请求和未完成检查。新分数只能来自通过验证的 Muse 输出：0–100 的整数，或 null（不评分）。这是未经校准的风险指示值，不是损失概率、诈骗百分比、身份信任分或安全保证。没有数值阈值、规则加分、权重、最低分或兜底分。定性规则信号独立保留，可能在模型评估之外继续提示警告。旧规则分数标记为历史记录。

numeric_assessment_basis 证据门槛禁止语义未解析的类型化消息仅凭哈希、编码成功、账户/verifier 代码或地址存在、通用权限警告或无关原生币余额取得数字。条件性数字必须引用与本次请求绑定且具实质意义的合格观察。这是证据要求，不是固定评分公式：已解析请求仍可在保留缺口的同时评估，合理弃权继续有效。未知自定义字段名不会被提升成代币转移、支出上限、接收人或 nonce 语义。

必须包含的维度 参考证据
Authority（权限） spender/operator、资产、数量、期限、撤销及后续使用范围
Exposure（敞口） 同种资产的余额比较、费用，以及证据支持的潜在影响
Execution（执行） 调用或分叉实际支持的调用与资产变化
Identity（身份） 账户、网络、来源和目标的一致性，以及取得的信誉观察
Protocol（协议） 有证据支持的滑点、退出、清算或合约控制机制
Deception（诱导） 可观察来源/消息/请求不一致，以及支持的钓鱼情报

各维度均为定性评估并引用证据 ID，不是数值子分数，也不取平均。证据置信度描述所提供证据包的支持程度，不是校准后的概率。缺少信誉数据不能证明身份恶意；有限授权不自动等于无害；未来执行未知也不会抹去已被证实的权限授予。

后端拒绝虚构引用、维度缺失/重复、无依据的确定性/蜜罐断言及不一致弃评；nonce/domain 声明校验覆盖摘要、原因、各维度、行动建议和缺失数据文本，包括条目索引、匹配方向、否定和条件性建议，并要求对应实际 RPC 观察。自然语言校验仍只是部分防护，不证明所有句子正确。每个 low/review/high 维度，必须引用至少一条工具计划之外、状态并非 unknown 的观察。评估范围记录此次请求实际未完成的检查与缺失证据；任何未知检查/缺口、模型发现的缺失、过旧/缺失/未来观察时间戳、公链区块来源/新鲜度失败或同高度冲突哈希都会阻止整体 low 或 strong 证据支持程度。完整 complete 与缺失列表继续显示；包字段为 assessment_scope，报告属性为 assessmentScope，策略名 observable-request-v1。允许的 low/strong 仅针对可观察请求范围，不证明身份可信或未来安全。有效弃评保持无分数。

输出校验修复和 HTTP 500/502/503/504 暂时性错误恢复共用最多一次额外请求，必须单独原子预留额度。两次合计 50 秒，第二次最多 25 秒，剩余不足 5 秒不启动。认证、额度、429、普通网络失败、超时、拒答、不完整封装和有效弃权不会自动重试。无效输出不会被本地分数替代；严格白名单只读查询在预留模型额度前标记无需评分。

Evidence quality（证据质量）清单列出各状态数量、按来源统计的已观察/未知数量、可用网络/区块/哈希/时间出处、同链上游区块混用、同链同高度哈希冲突，以及捕获方式和凭据归属。它会标记早于报告生成时间 5 分钟以上的观察、缺失或无效时间戳，以及超过未来 30 秒的时间戳。这些是诊断信息，不是风险分、覆盖率或置信概率。采集器记录时间不证明上游数据的实际年龄。pinnedRpc 优先使用规范区块哈希选择器；区块号已确认状态组采集前后核对链和完整区块头，复核失败丢弃关联状态组。这不证明提供方诚实，不形成全局原子快照，也不能防止未来重组。哈希冲突需要重新独立检查。分叉区块与上游快照分别记录。

证据行中的 pass 表示该项观察成功；warning/risk 描述该项信号；unknown 表示不可取得、不支持或未完成。工具计划不等于已完成观察。代码、代币名称、接口和熟悉的 selector 都可能具有欺骗性。成功调用或卖出只描述当时状态，不能保证未来行为。

Snap 优先展示最多 24 条证据、6 行主要参数和 6 条缺失检查摘要。使用报告 ID 在 Check history 查阅完整报告。显示截断不意味着被省略检查已经通过。旧的非英文历史报告保留原文，不凭空翻译或重新评估。

8. 了解准确字段提取与覆盖边界

本轮还增加 DAI 结构 Permit、ERC-3009 单次转移授权、Safe 结构控制/执行、有界递归封装摘要、V3 仓位状态、部分桥提款/完成参数和通用 withdraw(uint256)。它们是有边界的候选适配器，不是全协议支持。已确认 nonce 仍固定区块，另有独立未固定的节点 pending nonce 视图，不取得原交易内容或替换规则。67 个钱包案例现包含 8 个简化账户交易和 4 个 DAI/ERC-3009 候选签名；其他新路径有 API/代码测试，不代表官方协议或公网钱包验收。详见扩展能力与验收边界。

解码器提取受支持的 ABI 字段和被签名类型实际包含的消息字段，不会仅凭操作关键词猜测风险。README 操作表和中文覆盖指南列出全部类别。典型示例如下：

请求 发送给 Muse 前提取的字段与检查 剩余边界
ERC-20 授权 合约、spender、amountOrTokenId；标准/余额/allowance 读取及可选分叉与情报 与 NFT 共用 selector、欺骗性标准、spender 身份及未来使用
V2 兑换 路径、输入、最小输出、接收方/截止时间；选定分叉上的买入→授权取得的代币→反向卖出，以及 gas/变化量 路由有限；损耗包含价格影响和费用；卖出失败可能有多种原因

DAI 权限来自 allowed 的参考语义推导；ERC-3009 承诺单次精确数量，Permit2 transfer 为单 nonce 上限，后两者都不是持续 allowance。ERC-3009 当前余额不足会明确记录，不制造较小可消费转移量；空 calldata 的 DELEGATECALL 仍是委托代码执行，不是原生币转账。

支持的 EIP-712 无符号整数在风险解释前，会统一等值的十进制、十六进制与前导零表示，且保持被签 digest 不变。零地址按角色解释：支持的 NFT approval/Permit 撤销不会被误报为资产销毁；实际转账接收方及所有权变更仍按各自语义检查。transferFrom 的资产所有者与调用者分开；当前余额不足描述为执行/敞口问题，不再错误解释为授权覆盖未来入账。

EIP-712 风险字段必须能沿声明的签名类型图到达。额外但未被签入的 JSON 字段，不能证明已签权限、金融金额或 owner 不匹配。Permit2 从实际签名者取得 owner。标准 Permit2 的 expiration=0 表示提交区块的时间戳，不是签名前已到期，也不是自动撤销。非零但已过去的 expiration 被消费时仍可能引起状态变化。引用地址或匹配的 domain 不等于代码认证。

SIWE 风格文本按照受限的 EIP-4361 格式检查：账户/头部、必填 URI/version 1/chain/nonce/issued-at 字段及其顺序、nonce 格式和长度、到期/not-before/本地时钟，以及最多 16 个规范化资源来源。source/domain/URI 差异继续展示。远程登录 nonce 存储始终未验证；此检查不能证明 nonce 由谁签发或是否一次性使用、受众/会话是否接受、生成的签名是否有效，或网站是否诚实。托管的完整消息认证独立验证其自身挑战存储。

Snap 通过 endowment:ethereum-provider 在签名洞察期间尝试短时只读 eth_chainId，并单独记录带时间戳的 signature.providerContext。签名钩子没有与请求绑定的链：本地/EOA 请求保留 chainId: 0。托管合约身份只有在 provider 观察匹配时，才使用其已验证绑定链作为认证/取数范围；provider 链缺失或不匹配时要求重新连接，不生成评分。这不证明发起 dApp 的签名网络，也不把 provider 观察冒充签名 domain。签名者来自 signature.from；Snap 不会仅为检查额外请求选账户权限或新签名。

独立、固定区块的 RPC/balance/code 读取，仅在关联快照组通过链/区块头一致性核对后，才在其他接口读取失败时保留成功观察；区块头缺失或不一致会丢弃整个关联状态组。已确认 nonce 和提供费用/当前 base fee 的比较属于可观察检查，不保证待处理交易替换或未来打包。可识别的 EIP-7702 委托指示代码可产生一跳委托代码/哈希读取；实际元组密码学和有条件状态已有有界适配器；递归策略审计、完整 envelope 执行与资产 ERC-1271 接受仍不完整。一般有效类型消息即使 nonce 语义不支持，也可进行 DOMAIN_SEPARATOR 比较。

基础调用和分叉执行保留请求提供的受支持交易 type、gas、费用与 nonce。缺少 gas limit 时使用并记录模拟默认值。不支持的 EIP-7702/blob/access-list/type，或格式错误的执行字段会明确记录为缺口，不把简化替代过程当作等价执行。分叉写入只作用于临时本地进程，不写入上游公网。不同采集器可能使用不同的已验证区块；执行会在记录的分叉基点之后挖出子区块。

显式资产读取最多 8 种资产，每种资产最多 16 个 NFT ID。一般 RPC 摘要限制嵌套、数组、字段和地址；分叉发现限制日志、资产以及调用深度/数量。隐藏资产、非标准日志、动态代码和不支持的嵌套调用仍可能无法观察。原始数量不等于美元损失；资产精度、NFT ID、份额、费用及底层资产需要各自的单位。

5 个类别没有代表性的可执行实验室案例：原始 eth_sign、权限/会话请求、UserOperation、网络配置和只读 RPC。其他类别仍有各方法特有的缺口。对于非 EVM 链、其他钱包、恶意软件、密钥泄露、交易所内部、任意链下投资宣传、目标链到账和未来管理操作，目前也没有完整集成。

9. 托管身份与发布运行

EOA 恢复证明同一密钥对 EVM 地址的控制，因此其身份仍按地址跨链使用。ERC-1271 登录则建立地址加已验证链的身份：网页/Snap 凭据、扫描、私有报告访问、删除和撤销均限定在该链。同一个合约地址在另一条链上可能有不同所有者。切换网络后，请在目标链重新登录并配对；Snap 健康和请求检查会拒绝不匹配或无法观察到的绑定网络。链绑定签名仅在 provider 观察匹配后，使用已验证身份链作为认证/取数范围，并不证明 dApp 的实际签名网络。

托管资源也按已验证身份隔离：EOA 使用地址键，合约身份使用 eip155:<chainId>:<address> 键。活动/最近扫描、每身份 AI 和取证预算、Snap 配对签发频率及活动凭据容量都使用该范围；该身份的网页和 Snap 会话共用额度。IP/全局限额以及服务总并发、总凭据容量仍由所有身份共享，不因切换链而增加。

首次按此身份策略启动时，会一次性使旧托管登录挑战及网页/Snap 凭据失效，因为旧记录没有区分 EOA 与合约身份。请重新登录并配对。已存报告、使用额度、配置和本地链资产保留，迁移不会删除它们。

托管用户先连接账户，点击 Verify current wallet identity 或 Sign to verify this wallet。核对完整 domain、URI、地址、chain、nonce 和 expiry。后端针对已保存的一次性消息验证 EOA 签名，或通过可信 RPC 对支持的已部署合约进行有界 ERC-1271 STATICCALL；仅核对该登录，不支持的策略/未部署账户失败。挑战 5 分钟后过期。成功登录创建有效 8 小时、仅保存在内存中的网页 bearer 凭据。刷新、更换提供者/账户或断开连接会清除浏览器身份；再次访问私有记录需要重新验证。

配对创建另一个绑定地址、有效 30 天的 Snap bearer，不会把网页 bearer 传给 Snap。后端 SQLite 保存 bearer 哈希、有效期、撤销状态和报告归属。历史、报告 ID 和证据按已验证地址隔离，合约身份还限定已验证链；Origin 从不作为认证。托管交易/消息发送者必须匹配该地址。网页用户可显式提交受支持的手动摘要；Snap 凭据只接受交易和消息扫描。历史/详情随身份变化和加载失败清空，取消或过时响应被丢弃，当前所有者列表中消失的选择会变成空。本地模式仍为同机共享工作台历史，托管模式才按所有者隔离。

Snap 签发以 SQLite 原子方式持久化限流：每分钟每身份 4 次、服务端观察 IP 12 次、全局 60 次。每身份最多 4 个活动 Snap 凭据，全局最多 8192 个；成功重载仅轮换自己的最早到期凭据。429 不改变已有配对，含 Retry-After: 60。过期凭据和旧限流记录使用索引清理。

运营者必须在 .local/service.env 配置真实 HTTPS 域名、自有 npm 包名和公开仓库，参考部署配置示例。密钥保留在仅后端使用的模型/RPC 文件中。在项目目录执行：

npm run build:hosted
npm run package:hosted
npm run start:hosted

构建将同一个 HTTPS origin/npm ID 编译到前端和 Snap。打包会检查成功构建的指纹，并创建隔离的、仅包含允许文件的 dist/release-snap npm 产物；打包不会发布。在该产物目录运行 npm pack --dry-run --ignore-scripts 可检查内容。托管服务在配置的 HTTPS 反向代理后，通过回环 8787 端口提供前端/API；参考 Nginx 示例，保留准确的 Host/origin。它不启动 Anvil 或本地 Snap 文件服务。在其终端按 Ctrl+C 停止。更换域名、包名或模式后，前端与 Snap 都必须重新构建。

托管模式不注册本地实验室/资金准备、legacy/demo/workflow、监控、示例、下载或合成 AI 测试路由；它实施钱包与全局额度、每个已验证身份一个活动扫描、可配置总扫描并发上限和速率限制。打包不代表已经部署、发布 npm、获得注册资格、完成独立安全审查或被浏览器钱包接受。邀请公众前须另行完成这些工作。默认构建仍是本地 Flask 集成。

托管隐私、上游预算与证据强化

在 POSIX 系统上，启动时会将磁盘数据库及已有 WAL/SHM 附属文件限制为仅所属用户可读写的 0600，新建数据库目录使用 0700。这些权限也会收紧已有数据库，但不加密数据，不能阻止同一操作系统账户、管理员或未保护备份的访问。

模型输入在发送前受限：序列化证据包最多 200,000 个 UTF-8 字节，每次完整模型请求（包括修复请求）最多 500,000 字节。超限不会悄悄删减证据后生成看似完整的评估：原始证据保留，该次失败分析不接受分数。超时、供应商失败、拒答/无效输出及有效弃评也都不会产生本地编造的兜底分数。

Vite 禁止直接通过文件路由读取 .local/、.audit-build/、.presentation-build/、.git/、环境/凭据文件及数据库文件，包括 /@fs/ 请求。秘密仍须保存在指定私有文件中；这些拒绝规则是额外防护，不意味着可以把开发服务器公开到互联网。

Sign out all sessions and revoke pairing 会以原子操作撤销当前身份范围内的凭据和未完成挑战：EOA 为该地址的全部会话，合约身份则仅限已验证链上的会话。Delete my stored reports 先要求确认，只删除同一身份范围的报告并撤销其凭据。其他身份和使用额度保留，不能通过删报告重置付费尝试限额。每次托管报告插入/更新都会在同一 SQLite 事务校验凭据仍有效且归属正确；撤销后的进行中请求不能把报告写回来。已发送给 Meta/RPC/情报服务的请求无法因删除而撤回或退款。

这里的删除是 SQLite 逻辑行删除，不保证 WAL 页、磁盘、备份或第三方日志中的历史字节被法证擦除。应用不加密数据库。自动保留默认关闭；运营者可在后端 .local/service.env 或进程环境配置以下非密钥项：

WALLETSHIELD_SCAN_WALLET_DAILY_LIMIT=100
WALLETSHIELD_SCAN_IP_DAILY_LIMIT=300
WALLETSHIELD_SCAN_GLOBAL_DAILY_LIMIT=1000
WALLETSHIELD_REPORT_RETENTION_DAYS=0

证据/RPC/分叉扫描预算独立于模型调用预算：托管扫描在采集之前原子预留六个范围（每分钟每身份 8 次、服务端观察 IP 16 次、全局 60 次，另有以上可配置 UTC 日上限）。任一范围耗尽就拒绝扫描，不扣其他范围，不启动采集器。计数持久化，重启不重置；拒绝/未完成检查不产生兜底分数。模型调用仍有独立限额。这是初始容量策略，不是公众规模吞吐或可用性保证；网络连通探测仍有自己的限额。可配置日上限范围：每身份 1–10,000、每 IP 1–100,000、全局 1–1,000,000。

保留天数 0 不删除已有数据。显式设置 1–3650 天时，每次启动及之后每分钟最多清理 100 份已过期且有托管所有者映射的报告，积压可能需要多批；年龄按报告创建时间计算。无所有者映射的本地历史、使用额度、其他应用状态和第三方副本不由该策略删除。

公链区块来源与采集时间分开记录。quality.blockFreshness 标出 RPC/隔离分叉区块时间超过 300 秒、未来超过 30 秒、缺少区块时间/hash 或链身份未验证的观察；这些缺口会阻止整体 low 和 strong 证据支持程度，不是评分权重。合成演示与本地链 31337 不按公链区块年龄限制，因为本地时钟可能人为设置；观察时间诊断另算，新近区块也不证明没有重组或节点不一致。

Muse 新增接收 evidence_admissibility（各维度可由哪些实际观察支持）与 claim_support（有界基本调用/分叉执行/分叉卖出的支持）。真实但不相关的引用不能支撑该维度。代币元数据/开源状态或卖出风险标记为零，不能单独支撑身份、诱导或权限结论；实际控制权标记可支持权限，卖出/税费观察可支持敞口/协议，负面身份断言须有绑定请求/链的已识别风险观察。后端对所有展示文字检查无依据的“官方身份”、绝对安全、未来执行/卖出保证与事实性美元损失断言，同时保留明确未知与条件建议。基本调用不是交易上链，分叉结果不是公网执行或未来保证。这些只是部分自然语言防护，不是形式证明或独立准确率/校准基准；本轮新增检查采用离线对抗样本，不证明当前线上 Muse 的准确率。模型成功响应流式限制为 150,000 字节，错误响应为 16,000 字节，超限会取消读取，拒绝无效 UTF-8；不会把原始供应商错误文本作为用户建议。资源限制不证明模型结论真实。

GoPlus 仍需显式开启。它从已识别的外层/路径/Permit2/批量字段中最多选八个代币与八个交易对手，不把桥的远端 token 或 delegatecall 目标直接当作本链代币。每轮最多十八个网络请求、四路并发、单请求 1.8 秒、总共 7.5 秒；响应缓存三十秒（最多 256 项），支持链列表缓存一小时。结果带 fetchedAt、cacheHit、cacheAgeMs、cacheTtlMs、providerAsOf:null、freshnessVerified:false；刚取得不表示知道供应商数据的实际日期。缺失标记、闭源/代理导致的遗漏、未查询/截断候选与未命中均是边界，参见 GoPlus 官方响应说明。

代币出资的规范 V3 single/path、exact-input/exact-output 保留有界依赖式分叉买卖适配器。原买入保留已有执行字段，衍生卖出按实际输入扣减和取得输出计算。移除部署绑定后，V3 原生币出资往返实验及路由专用 sender-sentinel 接收人别名不再支持；适用时仍可进行原交易通用模拟。候选池/factory 关联、tick/range 和有效流动性仅是观察，不认证官方池、报价或未来退出。不透明聚合器、不支持的资金/接收人及未来排序仍有缺口。钱包目录现为 67 个代表性案例；移除前的历史验收结果不认证当前缩小后的范围。

自动入口仍取决于钱包实际交付。MetaMask 当前仅显示 Critical 严重级别的消息洞察，并在进入 Sign 后展示；交易洞察有独立入口，参见 官方入口说明。权限、会话、UserOperation 等仍需显式 API 或配合的 dApp SDK 接入，不安装全局钱包拦截。托管登录支持 EOA 恢复及支持范围内已部署合约的 ERC-1271 精确登录消息核对；未部署/ERC-6492 和不支持的策略仍不可用。公开上线仍需真实域名/TLS、目标 Snap 发布与分发、浏览器钱包验收、安全备份恢复以及负载/故障测试。

10. 隐私与故障排查

未签名请求、证据和输出发送到所配置后端并保存在 SQLite。本地模式存储在本机，托管模式存储在运营者服务器。应用不加密数据库；提供托管本人报告的确认逻辑删除与可选有界保留策略，默认关闭。RPC 提供者会看到查询状态和分叉所需的地址/调用参数；启用的 GoPlus 接收受限的所选地址、代币及规范化公开来源；启用的 Meta 接收受限证据包，包括受限消息预览和解码字段，不包含完整 calldata/历史或密钥。修复会重新发送该证据及受限的被拒输出。store:false 只是请求选项，不是对供应商日志行为的全面保证。

实验室和中性测试生成的签名留在浏览器。托管登录签名会按设计发送以完成认证，但不会持久化。不要把秘密放入未签名数据，过滤不是通用秘密检测器。捕获渠道记录的是凭据来源，不是钱包/Snap 代码实际执行的密码学证明。

问题 恢复办法
钱包不可用或扩展选错 在桌面浏览器打开本地 URL，选择目标提供者并授予账户访问。
Snap 已安装但配对失败 阅读失败阶段，检查 8080/8787，重新构建、刷新、加载和配对，再核对当前账户。
没有洞察或报告 钱包可能在触发钩子前就拒绝请求。检查入口是否支持、Snap 健康状态和后端可用性；不能把 API 报告算作钱包送达。
本地案例回滚 确认链 31337、最新部署、余额和案例前提；链重启后重新准备资产。
RPC 已配置但没有数据 检查真实端点可达性、链 ID、服务额度和历史状态支持。
没有 AI 数字 查看 ai.status 和消息：模型禁用/未配置、额度、失败、拒答、无效输出和诚实弃评都可以合理地保留无分数。
无法访问托管记录 重新验证正确的钱包；刷新会清除仅内存中的会话。配对令牌和网页令牌职责不同。
旧报告似乎不一致 对比时间、版本、来源与链重置情况；历史文字和结果会保留。

运行 npm test、npm run typecheck 和 npm run build 进行离线/静态回归检查。npm run test:security 会启动自己的隔离测试节点。test:chain 和 test:lab 需要运行中的本地部署，并对其快照/恢复；运行时让浏览器保持空闲。这些测试使用节点账户，不验证浏览器 Snap 送达。完整验收需要手动发起钱包请求、匹配到 Snap 报告、看到证据，并单独记录钱包结果。任何自动化测试数量都不证明普遍检测能力或已经适合公开生产使用。

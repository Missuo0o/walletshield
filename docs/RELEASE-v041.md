# WalletShield 0.4.1：网页、Snap 与取数说明同步

本轮按当前实现整理 30 类操作说明；没有把“写了说明”当作新增完整防护能力，也未扩大签后监控或强制阻止范围。

## 网页

- 将“密钥已保存”和“最近一次 AI 调用结果”分开，避免把非空配置误认为连接成功。
- 场景标明实际接入方式：交易 / 消息签名入口，或目前需主动提交。演示数据另行标注。
- 每条综合结果可展开“本次分析范围与 AI 数据”，看到尝试取数范围、未确定内容和进一步实现的条件。
- 全部类别共用一份说明，可从网页直接下载 [AI 取数与能力边界](AI-COVERAGE-GUIDE.md)。
- 更新钱包接入页，说明 0.4.1 的入口限制，并区分本地授权测试页和综合 EVM 请求检查。

## Snap

- 首页说明转账、NFT、兑换、借贷 / 金库和其他部分协议路径，以及手动入口和未接入范围。
- 交易 / 消息确认页增加主要参数、类别边界、缺失摘要及总数；保留 AI / 规则来源、解释、检查依据和记录 ID。
- 主要参数限 6 项，长值截断；缺失摘要限 6 项，完整内容在工作台。主要参数中的金额标记为原始单位，不能把 raw 整数当展示金额。
- 兼容早期没有结构化 operation 的返回值；不因此猜测协议分类。
- 未增加钱包权限，也未替用户安装 / 签名；用户需要到“钱包接入”重新加载 Snap 0.4.1，钱包内实际展示仍需用户验收。

## 说明内容

逐项记录：接入方式、当前覆盖程度、AI 的取数范围、尚不能确定的内容、能否补齐与原因。另有数据流、隐私、规则与模型分数、具体实现位置。

区分可开发的协议适配、需要外部数据或钱包合作的集成、只能做情景估计的未来风险，以及不能从缺失输入中推断的事实。模型没有自动联网 / 链上工具，后端才是取数方。

共享来源为 src/security/coverage.ts；网页与 Snap 直接使用它，说明由 scripts/coverage-guide.ts 生成。运行 npm run docs:coverage 更新文档，构建时自动同步；--check 可验证未过期。

## 验证

- 79 项自动化测试通过，包含本轮入口分类、参数显示边界、缺失计数、下载不触发模型、Snap 首页 / 两个确认入口的范围展示。
- 类型、网页和 Snap SES 构建通过；Snap 清单哈希自动更新。
- 浏览器已验证手动权限场景、借贷场景的说明面板和真实说明下载；下载内容与项目文档逐字节一致。随后浏览器连接中断，未保存本轮新版截图。
- 本轮只运行固定演示，不重复调用 OpenAI，不发送真实交易，不修改或重建本地链。
- 真实 OpenAI 评分仍未成功：最近已知固定合成样本返回 HTTP 429，待用户处理额度 / 限流后联调。

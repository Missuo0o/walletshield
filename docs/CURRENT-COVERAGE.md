# Current coverage and remaining limits

[English](CURRENT-COVERAGE.md) · [简体中文](CURRENT-COVERAGE-zh.md)

This describes the current v0.4.1 implementation after the correctness, validation, identity and dependency repair. It is a capability matrix, not an accuracy certification. Install/configure/run instructions are in the [README](../README.md) and [user manual](USER-MANUAL.md); exact per-profile extraction is in the [generated coverage guide](AI-COVERAGE-GUIDE.md).

WalletShield provides **pre-sign risk advice** for one unsigned EVM request. It does not force blocking or continuously monitor after signing, as defined by the current product scope. **30 analysis profiles and 66 representative local cases (51 transactions, 15 messages, 25 profiles represented) are not a percentage of risks covered.** Other methods, deployments, states and adversarial inputs can behave differently.

Current checks use the wallet-supplied unsigned request, source origin/network metadata and successfully collected RPC, intelligence and simulation evidence. Muse assesses observable request signals, including supported source/message/request inconsistencies. Chain/provider/execution context means technical observations. Historical reports and acceptance artifacts retain their original recorded data.


## Current evidence and integration additions

Current Muse output uses `walletshield-facts-v1`: exact selected subject/field/value/source/chain/block/time/scope facts, with per-reason and per-dimension `fact_ids`. Historical output remains readable. The backend verifies observation copying and relevance, not the truth of every provider response or free-form sentence. Scores remain Muse-only, with no fixed numeric weights, floors or fallback.

Optional `.local/registry.json` contains operator-reviewed deployment/code/implementation bindings, reference price feeds and reviewed OP bridge routes. `ENABLE_SOURCE_VERIFICATION=1` separately enables bounded Sourcify source-match observations; GoPlus remains a separate opt-in. No official deployment or dollar peg is invented by default. Prices are references, not executable quotes or guaranteed loss.

Bounded additions include Seaport committed items/current state, Permit2 witness outer commitments, version-bound UserOperation state, EIP-7702 tuple cryptography/conditional state, actual fork before/after selected authority/vault/lending observations, expanded V3 route experiments and candidate pool state. An explicit dApp provider wrapper supplies cooperating-app requests; it does not create a global wallet interceptor. Hosted ERC-1271 support validates this login only, not future asset signatures.

The Wallet and network panel reports configured registry counts/source-verification state and bounded read-only RPC capability observations: a fixed pinned call, one historical balance and a fixed trace probe. A successful probe is not a complete archive/trace guarantee. Registry and price enrichment remain inactive with empty lists; populate independently reviewed network/address/code records before relying on those adapters. The page’s network-switch advisory uses the explicit SDK for that page only.

`npm run evaluate:ai` runs a hash-pinned synthetic validator suite with zero model/RPC calls. It does not measure live Muse accuracy. Paid evaluation needs explicit `--live --confirm-paid`, selected cases and a call budget; it is never automatic.

See [evidence, configuration, exact tools/fields, SDK, evaluation and remaining boundaries](RELIABILITY-AND-INTEGRATION.md).

## What this repair changes

- Equivalent supported unsigned EIP-712 integer representations (decimal, hexadecimal or leading zeros) now normalize before interpretation while retaining the signed digest. Extra uncommitted JSON properties still cannot create signed authority.
- On-chain Permit2 reads keep its two allowance layers separate; failure of one does not erase or substitute the other. Neither read authenticates the contract.
- Zero addresses are interpreted according to their role. Supported NFT approval/Permit revocation is not mislabeled as burning the NFT. Actual transfer/burn/ownership-change meanings remain separate.
- transferFrom distinguishes asset owner, caller and recipient. A current balance shortfall is an execution/exposure issue, not proof of approval over future deposits.
- AI nonce/domain assertions are validated throughout summary, reasons, dimensions, suggested action and missing-data text, including indexed entries, direction, negation and conditional advice. Required evidence must actually match the claim. **These natural-language guards are partial; they cannot prove every sentence true.**
- History clears on account/provider/disconnect and failed reloads; canceled/stale asynchronous responses cannot restore old private rows/details. A selection outside the current owner list is cleared. Local mode intentionally remains a shared workstation history; hosted mode provides owner isolation.
- Hosted pairing is bounded atomically and persistently: **4/address/minute, 12/server-observed-IP/minute, 60/global/minute; maximum 4 active Snap credentials/address, 8192 globally**. Successful re-pairing rotates only the owner's earliest-expiring credentials. Denial changes no existing credential or issuance bucket. Expired token/rate cleanup is indexed. The global ceiling is an initial service capacity policy, not unlimited public scale. Hosted Fastify trusts forwarded client IPs only from the loopback proxy; the supplied Nginx example overwrites X-Forwarded-For with its remote client address. Preserve that trusted proxy boundary rather than trusting arbitrary forwarded headers.

## What a Muse score means

Only `muse-wonder-1.0` supplies new numeric scores: integer 0–100 or honest `null`. No local weights, score floors, fixed numeric bands or failure fallback are added. Six qualitative dimensions cite evidence: authority, exposure, execution, identity, protocol and deception. Missing reputation is not malicious identity; a familiar name is not verified identity.

The assessment scope records unresolved checks and missing evidence from this request. Any unresolved check/gap, model-identified missing data, stale/missing/future observation timestamp, public-block provenance/freshness failure, or conflicting same-height block hash prohibits overall low or strong evidence confidence. The full completeness flag and missing-check lists remain visible. The packet key is assessment_scope; reports store assessmentScope with policy observable-request-v1. Model judgment is not forced to be low, strong or numeric when these gates permit it.

A scoped low assessment means no obvious concern was identified in the evidenced request under the stated limits. It does not prove recipient legitimacy, off-chain honesty, complete evidence, future safety or a probability of loss. Known dangerous authority can still support a conditional numeric assessment when other dimensions remain unknown. If all dimensions lack actual support, no number is accepted. Output rejection/repair never manufactures a score.

## Intelligence, limits and missing inputs

- **GoPlus:** repository default is off; the development machine was explicitly enabled for this review. Verify `/api/security/status` for each installation. The adapter checks up to eight decoded token candidates and eight explicit counterparties plus normalized website origin on supported networks. It does not enumerate every path asset, every historical counterparty or arbitrary website contents. Missing/stale fields/non-hits are not proof of safety.
- **RPC:** configured Infura/other trusted nodes supply chain facts, not user-wallet connection or universal protocol understanding. More specific protocol reads require tested ABI/version adapters. Unsupported chains, missing archive state, provider quotas, false replies and reorgs remain possible.
- **Simulation:** isolated fork effects are observations at a recorded base state with bounded logs/assets/calls. One successful sale is not future sellability; a failed sale can have causes other than fraud. Some transaction fields/types are unsupported and explicitly remain gaps.
- **Additional trusted services needed:** reliable price/quote/liquidity data, verified official deployments/source/build identities, administrator graphs and broader reputation registries. These are not produced from model memory or an Infura key.
- **Wallet/dApp cooperation needed:** invisible permission/session/UserOperation entries, original raw-hash messages and relying-party nonce/session stores. A prompt cannot recover data never received.
- **Not established by this product:** non-EVM support, device malware/key compromise, exchange internals, arbitrary-code completeness, future prices/upgrades/blacklists/ordering/bridge arrival, or fund recovery. Forced blocking and post-sign monitoring are intentionally outside this advisory scope.
- **Reliability still unmeasured:** no independent held-out labeled benchmark of false positives/negatives, score calibration, repeatability or complete adversarial coverage. Automated/local acceptance counts do not substitute for it.
- **Public rollout still requires:** real HTTPS deployment, intended Snap publication/distribution, browser-wallet acceptance, secure backups/restore, retention/deletion policies, load/failure testing and operational review. Infura connectivity does not deploy the product.

## Hosted privacy, upstream budgets and evidence hardening

**Sign out all sessions and revoke pairing** atomically revokes every active web and Snap credential and pending login challenge for the current verified address. Other wallets are unchanged. Reverify and pair again to resume. **Delete my stored reports** requires an explicit confirmation, deletes only reports owned by this address and revokes all its credentials. Usage budgets remain, so deleting records cannot reset paid-attempt limits. Every hosted report insert/update checks the still-active credential and owner under the same SQLite transaction; a revoked in-flight request cannot restore its report. Requests already sent to Meta/RPC/intelligence cannot be recalled or refunded by deleting a report.

Deletion means logical SQLite row removal, not guaranteed forensic erasure from WAL pages, disks, backups or third-party logs. The application does not encrypt its database. Optional report retention is disabled by default. Set the following nonsecret operator settings in backend `.local/service.env` or the process environment:

```dotenv
WALLETSHIELD_SCAN_WALLET_DAILY_LIMIT=100
WALLETSHIELD_SCAN_IP_DAILY_LIMIT=300
WALLETSHIELD_SCAN_GLOBAL_DAILY_LIMIT=1000
WALLETSHIELD_REPORT_RETENTION_DAYS=0
```

Evidence/RPC/fork scan budgets are independent of model attempts: hosted scans reserve all six scopes atomically **before collection** (8/wallet/minute, 16/server-observed-IP/minute, 60/global/minute, plus the configurable UTC-day limits above). An exhausted scope rejects the scan without charging the others or starting collectors. These persistent counters survive restarts; rejected/unfinished checks do not fabricate scores. The separate model-attempt budgets still apply. These are bounded initial service policies, not a throughput or public-scale availability guarantee; network-connection probes have their separate limits. Allowed daily settings are 1–10,000 per wallet, 1–100,000 per IP and 1–1,000,000 globally.

Retention `0` preserves existing data. An explicit value from 1 to 3650 days prunes at most 100 expired owner-mapped reports at startup and each minute; a backlog can require multiple batches. Age uses the report creation time. Unowned local history, usage budgets, other application state and third-party copies are not removed by this policy.

Public-chain block provenance is separate from collection time. The `quality.blockFreshness` inventory flags RPC/isolated-fork block timestamps older than 300 seconds, over 30 seconds ahead, missing block time/hash or unverified chain identity. Such gaps prohibit overall `low` and `strong` evidence confidence; they are not score weights. Synthetic demonstrations and local chain 31337 are excluded from public-block age gating because local clocks can be artificial. Observation-time diagnostics remain separate, and reorganization/provider consistency is not proved by a recent block.

Muse now receives `evidence_admissibility` (which real observations can support each dimension) and `claim_support` (bounded basic-call/fork-execution/fork-sale support). A real but irrelevant citation cannot justify a dimension. Token metadata/open-source status and no-hit (zero) sellability flags do not by themselves support identity, deception or authority; actual control flags can support authority, sale/tax observations can support exposure/protocol, and adverse identity claims need request/chain-bound recognized risk observations. Bounded validation checks all displayed text for unsupported official identity, guaranteed safety/future execution/sellability or factual USD-loss claims, while preserving explicit uncertainty and conditional advice. A basic call is not transaction inclusion; a fork result is not live execution or a future guarantee. These guards remain partial language checks, not formal proof or an independent accuracy/calibration benchmark. New checks used offline adversarial fixtures; they do not establish current live Muse accuracy. Successful model response bodies are streamed with a 150,000-byte cap; error bodies have a 16,000-byte cap, oversized reads are canceled and invalid UTF-8 is rejected. Raw provider error text is not exposed as user advice. These resource bounds do not verify model truth.

GoPlus remains opt-in. It derives at most eight token and eight counterparty candidates from recognized outer/path/Permit2/batch fields; bridge remote-token fields and delegated-call targets are not blindly relabeled as local tokens. At most 18 network queries run with four-way concurrency, 1.8 seconds per request and 7.5 seconds total. Responses cache for 30 seconds (256 entries); supported-chain discovery caches for one hour. Each result exposes `fetchedAt`, `cacheHit`, `cacheAgeMs`, `cacheTtlMs`, `providerAsOf:null` and `freshnessVerified:false`: a recent fetch is not a known upstream data date. Missing flags, closed-source/proxy omissions, unqueried/truncated candidates and non-hits remain limits. See [GoPlus response details](https://docs.gopluslabs.io/reference/response-details).

Canonical V3 single/path exact-input/exact-output variants now have bounded dependent fork buy/sell adapters. The original buy keeps its supplied execution fields; the derived sale uses observed input debit and acquired output. Native funding requires matching maintained router/wrapped-native records. Candidate pool/factory association, tick/range and active liquidity are observed when readable; they are not authenticated pool identity, a market quote or a future exit guarantee. Opaque aggregators, unsupported funding/recipients and future ordering remain gaps. The wallet catalog remains 66 representative cases; adapter tests are separate from real-wallet/Snap and live-model acceptance.

Automatic coverage still requires actual wallet delivery. MetaMask currently displays message insights only at Critical severity and after advancing to Sign; transaction insights have a separate entry point. See the [primary entry-point documentation](https://docs.metamask.io/snaps/reference/entry-points/). Permissions, sessions, UserOperations and other wallet RPCs require explicit API submission or a cooperating dApp SDK integration; no general wallet interceptor is installed. Hosted login supports EOA recovery and bounded deployed-contract ERC-1271 validation of the exact stored login message only; undeployed/ERC-6492 accounts and unsupported policies remain unavailable. Public domain/TLS, intended Snap publication/distribution, browser acceptance, secure backup/restore and load/failure testing are still required before a public launch.

## Dependency status

The repair updates `@fastify/static` to 10.1.7 and lockfile overrides to `tmp` 0.2.7, affected `bn.js` 5.x to 5.2.5 and `uuid` below 11.1.1 to 11.1.1. At the repair audit, production-only `npm audit --omit=dev` had **zero known alerts**. The full audit retained **12 low-severity affected-package entries** in the `elliptic` development/build-tool chain with no available patched upstream resolution. These are time-specific audit results; not all dependencies are vulnerability-free, and counts do not prove source or deployment security. Run both audits again before release and evaluate remaining build-tool risk.

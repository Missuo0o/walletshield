# 完整复测与修复 — 2026 年 10 月 27 日

本轮从 `3c4cd58e5bc8cb30e4389f332d2aa5ad8b6d4be4` 开始，在 Node.js **24.22.1** 下完成。此前 592 项测试全部通过，但进一步定向复现仍发现了问题。下列问题已修复并加入回归测试。本轮属于内部复测，不是外部安全审计，也不表示测试了所有可能的钱包操作。

## 发现并修复的问题

| 问题 | 原来的影响 | 修复后的行为 |
| --- | --- | --- |
| 嵌套数量的资产归属错误 | fork 授权额度可能归到钱包而不是代币，金库份额、底层资产和头寸的不同代币单位可能混淆。 | 按采集器和精确字段绑定代币、金库份额、账户、token0/token1 与往返实验的输入/输出/原生币单位；Permit2 批量数量逐项绑定代币。 |
| 元数据可以支撑资金风险维度 | 人工构造的严格模型回复，仅用 `simulationOnly=true` 支撑高资金敞口，原校验仍会接受。 | 当前策略 **`muse-evidence-v7-quantity-bound-facts`** 使用来源、检查 ID、精确路径和数值类型的正向允许表。来源与未执行控制项标记不能独立支撑任何已评级维度；成功执行属于执行证据，不是资金数量。 |
| 有意义的已解析数量被遗漏 | 原生币转账额、ERC-20 转账额或规范 Permit 额度无法用于支持资金敞口。 | 按明确操作类别保留这些数量；共享 `approve`/`transferFrom` 整数须先观察到 ERC-20 标准。NFT ID 和含义不明的自定义签名数字不会当成资产数量。这些约束不是固定加分或权重。 |
| Snap 可能展示其他请求的报告 | 来自另一条链或另一目标地址的结构正确报告，可能通过展示校验。 | 交易和签名钩子都先比较后端回传请求与实际发送内容。检查网络、来源、发送方、目标、金额、调用数据、费用、nonce、委托列表、签名内容和提供者上下文，比较有数量/深度边界。不能据此证明恶意后端可信，也不能证明相同请求的证据始终新鲜。 |
| 发布包的 manifest 校验不通过 | 构建后更改名称、包名或仓库仍保留旧校验和，仓库信息也可能与 package 不一致。 | 先完成最终元数据，再计算官方校验和；验证实际复制的 bundle/icon，并调用官方 manifest 检查器。篡改内容或仓库不匹配会失败。打包本身不会发布 Snap。 |
| 构建依赖漏洞和测试时序不稳定 | 已安装的 `body-parser` 2.x 存在公开高危公告；一个账户连接失效测试的 10 毫秒期限会在并行负载下竞争。 | 将受影响依赖固定至 **2.4.0**；测试改用明确的调用进入信号，并立即注册拒绝断言。产品超时行为不变。 |

v7 字段回归包含 **30 个覆盖标签 × 18 种采集器形状**，检查超过 5,000 个候选字段。这是离线证据约束，不是对 30 个真实协议的现场验证。测试里的 88 等数字是人工校验样本，不是产品评分常量。数字仍由 Muse 给出；有依据的弃权仍保留。历史记录不会自动重新评分或改标为 v7。

从临时链收集新证据。上游代理允许读取，拒绝写入并关闭两种 trace 方法，分析通过隔离 fork 补充。为保证实验可控，关闭外部信誉查询。密钥保留在后端配置中。

| 案例 | 最终接受的结果 | 真实 API 请求 |
| --- | --- | --- |
| 金库存款，区分底层资产与份额 | **24/100** | 两次：首个回复包含缺少依据的具体观察断言，被拒绝；一次修正后通过。 |
| 不透明的自定义类型订单 | **无法给出数字** | 一次：资产授权语义不足，属于有效弃权。 |

总计 **三个完成的分析、四次付费 Meta 请求**，包含第一次被拒绝的输出。最后将四个原始回复按最终 v7 代码离线重放：首个仍被拒绝，三个最终结果仍通过，未再调用 API。分析期间源链区块与 nonce 保持不变，上游分析写入为零。

这些数字是特定案例的未校准指标，不是固定规则分数、诈骗概率或检出率。三个案例不能证明稳定性或漏报率。被拒绝的输出也会消耗额度；一次有边界的修正不能保证模型总能生成有效结果。

## 对产品的影响与仍需验证的内容

- **本轮没有重新完成真实 MetaMask 弹窗验收。** 自动化钩子、模拟提供者、本地节点签名与实际浏览器送达是不同验证层。改动后需重新加载 Snap，再做真实钱包验收。
- Snap 只能收到钱包支持的钩子。权限、会话、UserOperation 等需显式接入的路径不会因此变成自动全覆盖；当前 EVM 接入也不覆盖其他链的钱包。
- 自定义协议、非标准资产与不透明签名仍可能只有部分证据或无法评分。强行给数字会掩盖缺失语义。
- 当前快照/fork 无法保证未来执行、全部资产发现、未来可卖出、目标身份或跨链到账；缺失取数会明确保留。
- Muse 仍可能波动或漏掉风险；尚无独立留出标注集、分数校准与漏报率测量。
- 面向公众还需部署运维安全、分发兼容性和真实钱包/浏览器验收；配置 Infura 与 Muse 本身不代表公开生产就绪。

目前可以继续进行受控演示与范围内测试。这些边界影响的是“所有行为均受保护”和“公众真实资产可直接使用”的承诺，不代表已经实现的请求、取数、证据和风险提示流程无效。

## 真实 Muse 测试

本轮批量测试覆盖 **71 个代表性输入、全部 30 类分析 profile**。先在独立临时链中，针对 66 个实验室请求于操作前收集生产证据；随后把这些观察送入生产扫描 API、真实 Muse 与独立 SQLite。另有 5 个显式后端输入，涉及 raw signing、钱包权限、UserOperation、网络配置与只读分析；它们不代表 Snap 可以自动拦截这五类操作。

这是分两阶段的证据回放，不是 71 次同时发生的新钱包请求。原区块、观察时间和范围保持不变，较晚扫描可以正确报告证据陈旧；没有修改时间戳伪装新鲜，也没有放宽校验去追求数字。

| 阶段 | 真实 API 尝试 | 接受的分析 | 有数字 | 有效不评分 | 失败/拒绝 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首轮 71 案例 | 85，含 14 次输出修复 | 64 | 56 | 8 | 7 |
| 对 7 个失败各补测一次 | 7 | 恢复 3 个 | 恢复 3 个 | 无新增 | 仍有 4 个 |
| 最终逐案例结果 | **共 92 次尝试** | **67/71** | **59** | **8** | **4** |

首轮有一次 HTTP 500、六次超时。补测恢复了借贷前置授权、unwrap 和 ERC-3009 transfer；仍拒绝四个输出：

| 案例 | 最终拒绝原因 |
| --- | --- |
| SIWE 登录 | 数字与明确弃权互相矛盾。 |
| NFT 订单签名 | 出现缺乏支持的身份、安全、未来结果或美元损失断言。 |
| 登录域名不匹配 | 结构化输出/事实/引用校验失败；该次测试早于本轮更具体的错误提示。 |
| Permit owner 不匹配 | 高身份风险断言缺少校验器要求的相关不利观察。 |

这四个结果都没有被接受的分数，证据仍保留；不会拿规则数字兜底，也不会当成安全。超时、模型误解和输出拒绝仍然是产品限制。本轮按预算结束补测，同时保留首轮和补测结果，没有只展示成功样本。

59 个通过校验的数字不等于 59 个经过独立证实的正确风险判断。事实复制、引用相关性与一致性检查仍不能完全证明自然语言、算术、排序与任意提示注入都正确。本轮没有独立标注的准确率/校准基准；分数是未经校准的风险指标，不是损失概率。

## 真实 MetaMask Snap 验收

用户自行解锁测试钱包后，在 Chrome MetaMask Flask 重新加载并配对最新 Snap，完成两个真实弹窗路径：钱包 hook → 认证 Snap → 当前后端 → Muse → SQLite → 钱包显示。

| 实际请求 | Snap 与模型结果 | 钱包操作 |
| --- | --- | --- |
| 有限授权 100 LAB-USD | `paired-snap` 报告持久化，钱包内显示 **28/100** | 取消，未在上游本地链提交该额度。 |
| 普通本地测试消息 | `paired-snap` 报告持久化，模型完成但有效返回无数字 | 取消，没有将生成的签名交给合约使用。 |

这额外使用 **2 次真实模型请求**，与隔离批次的 92 次分开。两条实验室历史均显示 Received、模型结果和 Canceled in wallet。它只证明两个真实 UI 案例，不代表所有版本、硬件钱包、移动钱包或 66 种弹窗均验收。

普通消息 hook 没有提供与该请求绑定的 chain ID，Snap 正确地没有用独立的当前网络快照猜测。模型因未来授权/消费方式未知而弃权。这是有效完成的无数字分析，不是 API 连接失败。

同一报告可以同时出现 Unable to assess 标题和 Muse 数字：标题保留未完成的定性检查，数字仅评估已经取得的观察。因此标题不代表没有调用模型，数字也不代表安全检查全部完成。

## 已修复的问题

1. **交易 Snap 超时过早失效。** 旧实现收到 HTTP 响应头后就清除 abort timer，JSON 正文可能继续卡住。现在直到正文解析结束才清理计时器。新增测试模拟响应头已到、正文停滞，验证超时中止并显示无法评估。
2. **结构化事实校验错误提示过泛。** 缺失/重复事实、值与观察不符、事实与证据 ID 不匹配，以及理由/维度缺少事实支持，改为更具体的有限提示。新增测试验证三类错误，仍拒绝分数，没有改变提示词、评分或放宽标准。
3. **Snap 缺少仓库元数据。** 补充规范 GitHub 地址与 Snap 目录，重建 manifest 校验和；最终支持环境构建没有该警告。

用户原来的 8545 链保持不变。批量测试使用 git archive 副本、独立部署和独立端口，仅在私密副本替换回环地址。清理资产使用临时测试账户，不清空用户资产。两个真实钱包请求在检查后取消。公开记录不包含 API Key、私密 RPC URL、助记词、私钥、生成的资产签名、原始模型正文或钱包数据库；PPT 仍只保留本地。

## 仍然影响产品边界的内容

| 限制 | 影响 |
| --- | --- |
| 模型稳定性和耗时 | 合法请求也可能超时、弃权或被校验拒绝，不能承诺每次都有数字。 |
| 缺少独立准确率校准 | 可以提供有证据的建议，不能声称分数就是损失概率或已证明的攻击检出率。 |
| 钱包入口限制 | 普通交易/消息 hook 不会普遍交付权限、会话、UserOperation、网络设置，显式适配器需要合作方接入。 |
| 协议与资产解析有界 | 自定义语义、深层/不透明批量调用、非标准记账、未来代码变化和签名消费可能超出证据范围。 |
| RPC 与情报能力 | 本次公网 trace 不可用；配置 RPC 不等于拥有所有历史、trace、价格或威胁事实。 |
| 未来执行和经济行为 | 模拟成功不能保证未来能卖、流动性、无 MEV、跨链到账或签名后续使用。 |
| 公共服务验收 | HTTPS 部署、分发审核、并发与滥用、留存和事故恢复仍要按实际部署验收；只有 Infura Key 不够。 |
| 构建依赖公告 | 仍有低危上游依赖记录，需要等兼容修复并验证。 |

它们会影响“所有行为都受到保护”的宣传，不妨碍边界清楚的 EVM 签前风险建议原型与本地演示。强制阻止和签后持续监控仍不在用户要求的范围内。

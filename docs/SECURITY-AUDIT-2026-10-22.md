# WalletShield 当前能力、取证与评分核查

日期：2026-10-22。范围：本地 0.4.1 + Meta Muse Wonder；仅签名前风险提示，不强制阻止，不持续进行签后监控。这是本轮核查记录，完整 README 后续单独整理。

## 1. 本地资产准备

之前资产虽然已铸造，但网页没有完整展示和导入入口，也没有清晰区分基础资产与协议仓位。本轮新增固定区块资产清单、ERC-20“添加到钱包”、NFT 编号及持仓、协议仓位查询，并在准备完成后核对链上余额。

| 资产 | 准备行为 | 用途 |
| --- | --- | --- |
| 测试 ETH | 不足时补足到 10；已有更高余额不降低 | gas、原生币转账、兑换、包装、桥入口 |
| TEST-USD | 不足时补足到 5,000 | 保留原版授权测试资产 |
| LAB-USD / LAB-Q / LAB-BLOCK | 各不足时补足到 5,000 | 新实验室的授权、转账、兑换与协议测试；BLOCK 故意限制卖出 |
| ERC-721 LAB-NFT | 保证账户有一个测试编号；转走后重新准备可能生成新编号 | 单项授权、全量授权、NFT 转移 |
| ERC-1155 | 编号 1、2 各不足时补足到 10 | 单项及批量转移、operator |
| WLAB | 初始可为 0；须自己完成包装交易 | 解包测试 |
| 金库份额、抵押、债务、质押、流动性记账 | 只读取，不由后台替用户自动创建 | 必须按案例完成授权、存入、抵押等前置操作 |

所有资产仅在本机 Anvil 31337 有效，无真实价值。导入只影响钱包显示，不改变余额。准备会把实验控制合约 owner 重设为当前测试账户；它不是生产资产发放服务。实验合约调用前会核对网络、Anvil 与部署代码哈希；部分有前置条件的案例增加只读预检，错误会说明缺少哪一步。故意失败的卖出案例仍保留。

## 2. 入口、提取和交给 Muse 的内容

不是按“转账”“授权”等中文关键词猜测行为：交易先匹配 selector，用 ABI 解码并按同一重载重新编码核对；消息按签名方法、EIP-712 类型与字段分析。方法名称、同名合约和 ERC-165 声明都不证明真实协议身份。

流程：MetaMask 将实际未签名请求交给 Snap → 本机 Fastify 验证请求 → ABI / typed-data 解析 → 按操作路由取证 → Muse Responses API → 格式、证据引用与部分结论一致性校验 → 同一份报告回到钱包与网页。

| 操作类别 | 主要提取字段 | 工具与证据 | 保留的限制 |
| --- | --- | --- | --- |
| 原生币转账 / 合约收款 | from、to、value、来源、链、费用 | viem / RPC 固定区块余额与代码；eth_call；可选隔离 Anvil 模拟 | 收款方身份、付款目的、未来欺诈不由交易证明 |
| ERC-20 转移 | token、recipient、amount | 代币代码、symbol、decimals、余额、模拟净变化 | 不把原始数量当美元；无统一价格或真伪认证 |
| ERC-721 / 1155 转移 | owner、recipient、编号、数量 | ERC-165、ownerOf / getApproved / isApprovedForAll 或逐编号余额；副本变化 | 最多 16 个编号，不审定 NFT 价值和全部回调 |
| 单项 / 全量授权、撤销 | spender / operator、额度 / 编号、approved | 标准核对、当前余额、既有 ERC-20 allowance / NFT 权限 | 同 selector 可能不同语义；未来入账及权限滥用仍未知 |
| Permit / Permit2 | domain、网络、验证合约、owner、spender、额度、期限、逐项 nonce | EIP-712 编码；标准 EIP-2612 nonce / DOMAIN_SEPARATOR；部分 Permit2 三元 nonce / 位图；显式多代币信息 | 自定义、NFT / DAI / witness 等变体不完整；不执行未来消费 |
| V2 / V3 兑换 | 输入 / 输出代币、数量、最小输出、最高输入、路径、fee、接收方、期限 | 显式资产各自代码与单位；副本执行；受支持 V2 买卖往返 | V3 池、真实报价、MEV、全部路由 / 聚合器不完整 |
| 金库 | action、金额、份额或底层资产单位、receiver / owner | asset / preview / max / 总资产与份额；底层余额和额度、份额余额及可读精度 | 接口返回不证明真实偿付、价格或未来可退出 |
| 借贷 | asset、amount、onBehalfOf、模式 / 抵押开关 | 当前账户抵押、债务、可借额、健康因子和可得配置 | 不是完整操作后清算、预言机、利率压力模型 |
| 质押 / 流动性 | action、具名金额 / 最小值、代币、接收方、deadline | 资产余额 / 额度，代码与通用副本 | 锁仓、罚没、真实池定价、无常损失和退出规则需专属适配 |
| 桥 / claim / mint / burn | 目标、数量、接收方、证明项数、候选方法 | 本链调用、代码、资产差异 | 不证明目标链到账、Merkle 权益、发行价值 |
| 控制权 / 升级 / 部署 | 新 owner / role / 实现、value、字节数 | 当前 owner / paused / ERC-1967 槽；新控制对象代码存在性和哈希；副本 | 不审计所有新代码、存储布局和隐藏管理员 |
| 批量 / 未知调用 | 方法、有限子调用 selector 或输入长度、期限、数量 | 父交易副本、有限调用树与资产发现 | 未递归理解所有聚合器 / 子调用；未知保持未知 |
| 普通消息 / 登录 / 订单 | 方法、预览、域名 / 账户 / 网络、typed domain、白名单财务字段 | 有界文本、账户 / 域名不匹配、期限、类型编码与可得链上状态 | 不是完整 SIWE 会话验证、Seaport 履约模型或任意消息消费证明 |

每次最多查询 8 个显式资产。其他隐藏资产可能只由受限日志和调用树发现；无日志或非标准存储可能遗漏。外部 GoPlus 地址、网站与代币情报是可选工具，当前本地配置未启用，不能把“未查询”写成“无风险”。真实链 RPC / Infura 未在本轮验收；本地测试不需要 Infura。

发送给 Meta 的是有界结构化证据：请求公开摘要、解析字段、固定区块与取证结果、缺失项、必要消息预览、可选用户背景和金额单位说明。不会主动获取助记词、私钥，不发送 API Key、生成后的签名、完整历史或完整交易 calldata。消息和用户输入本身仍可能包含隐私；请勿填入秘密。

本地背景仅在明确的实验 session 与实际 Snap 请求精确匹配后合入，明确称为用户陈述。其他网站发起的操作不会自动获得聊天记录、页面完整内容或这些实验室背景。

## 3. 本轮修正的取证问题

- 独立读取每个资产的代码，修复调用目标代码与目标代币代码混用；兑换不再只读取输出代币。
- 补逐 NFT 权属、既有授权、1155 余额，标明查询上限。
- 补 Permit2 批量 nonce、极高额度标志与资产数量；Permit 无限额度也保留标志。
- 代币精度、原始单位、份额与底层资产明确区分；流动性金额具名。
- 同 selector 的重载按实际 selector 重新编码；非法尾随字节保持未识别。
- typed-data 编码未通过时不再保留“已完整解析”的操作结论。
- 期限优先与所查区块时钟比较，无链时钟时明确只按本机时间判断；跨采集器快照不假定完全同步。
- 长消息及批量摘要截断显式提示；普通消息的文本 / 十六进制表示可关联同一请求。
- EIP-7702 authorizationList / blob 特殊执行字段标明未覆盖，不执行删去字段的替代模拟。
- 外部情报仅接受有效标志 / 税率，空字段、非法字符串和查询失败保持未知。
- 模型等待时间与 Snap、网页预算统一；显示“正在分析”，区分超时、拒绝、HTTP 错误与结论校验失败。

## 4. 评分归属和严谨性

**新数字评分完全由 muse-wonder-1.0 生成。** 后台没有固定加分表、最低分或规则分数回退，也不对模型分数加权平均。规则仍产生“极高授权”“账户不一致”等文字信号；综合提示可能保留规则高风险，与模型的数字和文字判断分别展示。

Muse 必须输出六项：权限范围、资产暴露 / 费用、执行变化、身份一致性、协议机制、诈骗诱导背景。每项给判断、理由、实际证据 ID；另给总分 / null、总评、证据支持程度、建议和缺失项。证据支持程度不是概率。

后端拒绝越界数字、虚构证据 ID、重复 / 缺失分项、“无法判断但给数字”、未完成检查却声称整体低风险 / 证据充分、缺少依据却确认 honeypot 等输出。身份“高风险”也必须引用实际观测的警告 / 风险，而不能只因信誉未知机械认定。拒绝后显示无评分，不自行修成另一个分数。

这仍然不是经统计校准的诈骗概率，也不是安全证明。引用存在不保证模型每一句推理都成立；本轮真实输出审读就发现身份不确定被过度推断，随后加了校验。模型可能波动或被拒绝，不能声称相同输入一定得到相同数字。下一阶段应建设独立标注案例、正常操作对照、误报 / 漏报和重复运行评测，不能用几个演示分数证明准确率。

## 5. 哪些情况可能没有 AI 分数

没有简单的“某一类永远可评分”清单。转账、授权、兑换或签名在证据足够时都可获得本次风险指标；同一类别遇到未知协议、无 RPC、无法解码、特殊交易或只有不可逆摘要时，可能缺少支持有意义数字的事实。

- 模型主动返回 null / unknown：证据不足，不是调用错误。
- Key / 额度 / 模型权限 / 每日预算 / 限流 / 网络 / 超时：模型没有完成；不能用规则伪造分数。
- 模型给了数字但格式、引用、分项或结论校验失败：数字未被接受。
- 请求根本未被钱包交给 Snap：没有自动检查；网页不能凭空补造结果。

签名 nonce / domain 匹配只能说明当前可核验部分成立；未来消费交易仍未知。卖出失败也可能来自路由、流动性或余额，不能独立确定 honeypot；一次卖出成功更不能证明以后不会拉黑。杀猪盘还涉及对话、真实身份、投资承诺与平台业务，链上转账可能完全正常。

## 6. 尚未完整设计 / 接入的风险防护

| 内容 | 当前状态 / 原因 |
| --- | --- |
| EIP-7702 委托签名与 authorizationList 完整执行 | 能标记缺口 / 发现已有委托代码，但无完整委托验证器 |
| ERC-4337 / bundler / paymaster、会话密钥和权限限制 | 后端仅摘要兜底；无通用 Snap 自动入口或专属账户测试环境 |
| 添加网络、资产显示、连接账户及只读 RPC | 本地网页会实际调用必要方法，但 Snap 不全局拦截这些 RPC |
| 所有订单、NFT / DAI Permit、Permit2 witness、自定义签名 | 只有有限标准和财务摘要，需要逐协议适配与状态查询 |
| 所有路由 / 复杂聚合器 / 动态委托调用 | 不完整递归解析，资产 / 日志 / 调用树都有资源上限 |
| 真实 V3 流动性、MEV、闪电贷、精确滑点损失、完整清算 | 缺协议及市场模型、可信价格 / 报价和更多模拟路径 |
| 真正跨链到账、桥共识 / 托管安全 | 本地只有本链入口，未接双链与消息验证 |
| 收款方身份认证、地址投毒、官方代币 / NFT 真伪、全网威胁情报 | 尚无完整可信注册表、解析与行为情报系统 |
| 社交工程 / 杀猪盘全流程、交易所内部、设备恶意软件、密钥泄露 | 不具有这些数据或系统入口，不能靠 LLM 推断成事实 |
| Bitcoin / Solana、其他钱包与移动端完整入口 | 当前是 MetaMask 提供的 EVM 请求 |
| 未来升级、未来黑名单与管理员恶意行为 | 一次签前检查无法证明所有未来状态 |
| 签后监控、强制阻止 | 按当前产品范围不提供 |

因此，30 个分析分类、25 类有代表性钱包案例，不代表覆盖率达到某个百分比，更不能称“所有安全风险已覆盖”。

## 7. 验证证据和下一步

- 104 项自动化测试通过，类型检查、网页 / Snap 构建通过；本地资金准备、授权 / 消费 / 撤销；独立副本买卖、Permit、金库与借贷取证均已执行。
- `wallet-lab-acceptance.json`：54 个本地案例，43 交易 / 11 消息签名；新增资产清单与取证检查，测试后恢复原链快照。不是 MetaMask UI 验收。
- `ai-evidence-audit-initial-timeouts.json`：最初 18 秒预算下三个超时，全部保留无评分。
- `ai-evidence-audit-acceptance.json`：调整预算后三个真实 Muse 输出，约 16–19 秒；只验证连接、输出与当时校验，不证明准确率。
- `ai-evidence-audit-rejected-followup.json` / `ai-evidence-audit-followup.json`：后续更严格结论校验的拒绝 / 复测记录。最新 Permit 复测已完成六维输出并通过校验，55/100；此前被拒的结果仍保留。分数只属于该固定样本，应以最新复测状态为准，不能隐藏失败。

操作：刷新网页 → 钱包接入重新加载并配对 Snap（本轮改了展示与等待预算）→ 准备资产 → 查看余额 / NFT 清单、按需添加代币显示 → 按案例前置条件发起实际钱包请求。优先做无限授权取消、有限授权、撤销、NFT、受限卖出、Permit 账户 / nonce / 域名异常的对照。

仍需用户在 Flask 中完成实际 Snap 交易 / 消息弹窗验收；自动化节点签名不等于已验证钱包把所有请求交给 Snap。较长等待期间不要把尚未生成分数当作安全通过。
